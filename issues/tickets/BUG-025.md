# BUG-025: 2 項目のリストで空項目の Enter がマークを消さず、上に空行を挿入する

- **State**: Fixed
- **Reported**: 2026-08-19
- **Area**: editor/live-preview（@codemirror/lang-markdown の既定挙動）

## Summary

`- aaaa` → Enter → Enter と操作したとき、2 回目の Enter で空の箇条書き項目が
消えず、**その上に空行が挿入されて項目が 1 行下へ移動する**。
Obsidian や一般的な Markdown エディタでは 2 回目の Enter で項目が消える。

箇条書きインデント表示（`20f1097`）の作業中に報告されたが、**その変更が原因ではない**。
v0.3.0（`b102a66`）の `src/` と比較した実キー入力テストで、変更前後とも同じ結果に
なることを確認済み。以前から存在した挙動。

## Reproduction

1. `- ` を入力
2. `aaaa` を入力
3. Enter
4. Enter

観察（ディスク実内容）:
```
- aaaa
              ← 空行が挿入される
- ﻿            ← 項目が消えずに下へ移動
```

番号付きリストでも同様（`1. a` → Enter → Enter で `1. a` / 空行 / `2. `）。
ネストした項目では、空白だけの行が残ったうえで同じ段のマークが再生成される
（`- a` / `  - b` / `␣` / `  - `）。

## Expected

2 回目の Enter でマークが消える。空行は挿入しない。

```
- aaaa
              ← ここにカーソル。マークは無い
```

ネストしている場合は 1 段浅い項目になる（`- a` / `  - b` / `- `）。

## Cause

`@codemirror/lang-markdown` の `insertNewlineContinueMarkup` の**意図的な**分岐。

空項目で Enter を押したとき、既定ではマークを消すが、**「項目間に空行の無い
（tight な）2 項目リストの 2 番目」**という条件に当てはまる場合だけ、
「上に空行を挿入して loose なリストに変える」側へ分岐する
（dist/index.js の `// Move second item down, making tight two-item list non-tight`）。

条件は `first.to >= pos || second && second.to < pos || 直前の行が空 ||
config.nonTightLists === false` のいずれかが真ならマーク削除、という形。
3 項目目以降や既に loose なリストでは削除側に入るため、**2 項目のときだけ**
挙動が違って見えていた。ユーザーが「今までは消えていた」と認識していたのは
おそらくこの項目数の多いケース。

## Fix

`insertNewlineContinueMarkupCommand({ nonTightLists: false })` で当該分岐を無効化し、
`Prec.highest` の Enter バインドで `quoteAwareEnter` の次に試すようにした
（`src/editor/live-preview.ts`）。この設定はライブラリが公開している正規の
オプションで、パッチや再実装は不要。

実キー入力（Playwright）で変更前後を比較した結果:

| ケース | 変更前 | 修正後 |
|--------|--------|--------|
| `- aaaa` Enter Enter | `- aaaa\n\n- ` | `- aaaa\n` |
| さらに Enter | `- aaaa\n\n` | `- aaaa\n\n` |
| 3 項目目以降 | `- a\n- b\n- c\n` | 同左（変化なし） |
| ネスト 1 段戻す | `- a\n  - b\n \n  - ` | `- a\n  - b\n- ` |
| ネスト 2 段から | `- a\n  - b\n    - c\n   \n    - ` | `- a\n  - b\n    - c\n  - ` |
| 番号付き `1. a` Enter Enter | `1. a\n\n2. ` | `1. a\n` |
| 通常の継続 `- a` Enter `b` | `- a\n- b` | 同左（変化なし） |
| 引用 `> q` Enter Enter | `> q\n>\n> ` | 同左（変化なし） |
| 引用→非引用行（E-15） | `> q\nx\n` | 同左（変化なし） |
| 引用の継続（E-15b） | `> q\n> abc\n> ` | 同左（変化なし） |

引用まわり 3 件が変更前と 1 バイトも変わらないことを確認しており、
BUG-011 / E-15 への回帰は無い。

- **Fix commit**: 189d309
