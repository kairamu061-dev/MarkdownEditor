# BUG-029: リストの遅延継続行が、項目の本文位置まで字下げされて表示される

- **State**: Fixed
- **Reported**: 2026-08-20
- **Area**: editor/live-preview（リストのインデント表示）

## Summary

`- aaaa` → Enter → Enter → `a` と入力すると、`a` が箇条書きの本文位置まで
字下げされて表示される。見た目は普通の段落のつもりで書いた行なので違和感がある。

## Reproduction

1. `- aaaa` と入力
2. Enter → Enter（マークが消えて空行になる）
3. `a` と入力

観察: `a` が `aaaa` と同じ位置（弾丸の右）から始まる。

## Expected

行頭に空白もマークも無いので、通常の段落と同じ左端から始まる。

## Cause

インデント表示は「その行が属する ListItem」からマーカー幅を取り、継続行にも
同じ字下げを与えている。項目が複数行にわたるときに本文の位置を揃えるための仕様。

`- aaaa` の次の行の `a` は、CommonMark の**遅延継続（lazy continuation）**により
パーサ上は同じ ListItem の中にある。そのため継続行として字下げの対象になっていた。

行頭に空白が無い＝利用者が字下げを書いていない行まで対象にしていたのが行き過ぎだった。

## Fix

**行頭に空白もマークも無い行は装飾しない**ようにした（`src/editor/live-preview.ts`）。

`  continued text` のように利用者が実際に字下げして書いた継続行は、これまでどおり
本文位置に揃う。原文どおりに見せる、という切り分け。

確認: `- aaaa` / `a` の 2 行目が `padding-left: 6px`（通常の段落と同じ）・
テキスト開始 x=30 になることを実測。

- **Fix commit**: 259d7c5

## Notes

- 検証は開発機の headless Chromium。Windows / WebView2 は未確認のため `Fixed` 止まり
- **原文上は依然として同じ項目の一部**（遅延継続）である点は変えていない。
  他の Markdown ビューアで開くと `a` は箇条書きの一部として描画される。
  完全に段落として分けたい場合は、あいだに空行を入れる必要がある
