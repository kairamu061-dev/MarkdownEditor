# BUG-013: フォルダをリネームすると、その配下で開いているノートが保存できなくなる

- **State**: Closed
- **Reported**: 2026-07-30
- **Area**: file-explorer/file-ops

## Summary

フォルダ配下のノートを開いた状態で親フォルダをリネームすると、開いているノートの `currentPath` が旧パスのまま残り、その後の編集が「保存に失敗しました」となり保存されない（編集消失の窓）。ツリーから開き直せば復帰する。

## Reproduction

1. `フォルダA/ノートA1.md` を開く
2. 親フォルダ `フォルダA` を右クリック→リネーム（例 `FolderA-v2`）→ Enter
3. 開いているノートを編集する

観察: フッタに「保存に失敗しました」。編集はどこにも保存されず、開き直すとリネーム時点の内容に戻る（編集消失）。

## Expected

フォルダをリネームしても、配下で開いているノートは新パスへ追随し、そのまま編集・保存できる。

## Cause

`src/explorer/file-ops.ts` の `startRename` 確定処理が、開いているノートのパス追随を `!isDir`（リネーム対象がノート自身）のときだけ行っていた。フォルダをリネームしても、配下で開いているノートの `currentPath` が旧パスのまま残り、以後の自動保存が存在しない旧パスへ書き込んで失敗していた（Rust `rename_path`＝`fs::rename` でフォルダは移動済み）。折りたたみ状態 `collapsedDirs` も旧パスのままだった。

DnD 移動（`doMove`）は `remapPaths` でパス追随していたが、リネームは追随処理を欠いていた（コードレビュー指摘 3.1・実機フィードバック §2）。

## Fix

`index.ts` に `remapAfterRename(from, to)` を追加（`from` 完全一致と `from/` 配下を `to` プレフィックスへ置換。`currentPath` と `collapsedDirs` を更新）。`startRename` 確定時に `!isDir` 条件を廃し、ノート・フォルダ問わず `remapAfterRename(path, to)` を呼ぶ。DnD 用 `remapPaths` と共通処理 `remapPrefix` に集約。
