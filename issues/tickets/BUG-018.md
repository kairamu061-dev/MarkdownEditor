# BUG-018: テーブル装飾がカーソル移動のたびに全文書を再走査する

- **State**: Closed
- **Reported**: 2026-08-02
- **Resolved**: 2026-08-06（Windows 実機で動作確認・合格）
- **Area**: editor/live-preview（`table-preview.ts`）

## Summary

`table-preview.ts` の `StateField` が、選択（カーソル）変更のたびに `buildDecorations` を呼び、文書全体を `syntaxTree(state).iterate`（範囲指定なし）で走査＋全 `TableWidget` を再構築していた。テーブルを含む長文でカーソルを 1 回動かすだけで全走査が走り、`eq()` の `JSON.stringify` 比較も相まって体感の入力遅延になり得る。

## Cause

`live-preview.ts` / `code-block.ts` は `view.visibleRanges` にスコープしているが、`table-preview.ts` だけ全文走査。`StateField` はブロックデコレーション提供のため必須で `visibleRanges` を持てない（構造的制約）が、更新条件 `if (tr.docChanged || !tr.newSelection.eq(...))` が広すぎた（コードレビュー §2、前回 §4.1 の続き）。

## Fix

選択変更時は「カーソルがテーブル範囲に出入りしたときだけ」再構築するよう条件を絞った。`tableAt(state, pos)`（`resolveInner` の祖先を辿り Table ノードの `from` を返す軽量ヘルパ、境界取りこぼし防止に両 bias を見る）で旧/新カーソルのテーブル所属を比較し、変化したときのみ `buildDecorations`。テーブルの無い箇所のカーソル移動では再構築が走らない。複数選択は稀なので安全側で従来どおり再構築。

- **Fix commit**: `118e0a3`
