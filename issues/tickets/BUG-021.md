# BUG-021: シンボリックリンクで無限再帰クラッシュ / 保管庫外アクセス

- **State**: Closed
- **Reported**: 2026-08-02
- **Resolved**: 2026-08-06（Windows 実機で動作確認・合格）
- **Area**: file-explorer（`src-tauri/src/vault.rs`）

## Summary

2 点（いずれもシンボリックリンク未対応が原因）。

1. **無限再帰**: `build_tree` が `path.is_dir()`（リンクを辿る）でディレクトリ判定していたため、保管庫内に祖先を指すディレクトリシンボリックリンクがあると無限再帰し、`panic = "abort"` 設定のためスタックオーバーフローで復帰不能に落ちる。
2. **保管庫外アクセス**: `resolve_in_vault` のコンポーネント検査は文字列レベルのみ（`canonicalize` なし）で、保管庫内のシンボリックリンク経由で外部を読み書きするのを止められない（ローカル単一ユーザー向けのため実害は限定的だが「保管庫外に触らない」建付けと乖離）。

## Cause

コードレビュー §5。`build_tree`（`vault.rs:87`）の `path.is_dir()` はリンクを辿る。`resolve_in_vault`（`vault.rs:29-43`）は字句検査のみ。

## Fix

1. `build_tree` で `entry.file_type()`（リンクを辿らない）を使い、`is_symlink()` はスキップ。ディレクトリ/ファイル判定も `file_type` ベースに変更。→ 無限再帰しない・リンクは一覧に出ない。
2. `resolve_in_vault` に `guard_within_vault` を追加。解決先（未存在なら実在する最深の祖先）を `canonicalize` し、保管庫ルートの canonical 配下に収まることを確認、外れたら拒否。root を canonicalize できない場合（テストの仮想パス等）は字句検査に委ねて no-op。

- **Fix commit**: `118e0a3`

- Windows 実機での挙動確認（canonical の `\\?\` プレフィックス周りを含む）は次ラウンド推奨。
- コードレビュー（`tmp/コードレビュー/コードレビュー結果.md` §5）由来。
- **検証（2026-08-06）**: 自己参照のディレクトリリンクを張った保管庫を開いてもクラッシュせず、ツリーに実ノートのみ表示（リンクはスキップ）。非管理者のため `mklink /D` が使えず、同じくリパースポイントで `is_symlink()` に捕捉されるジャンクション `mklink /J` で代替検証。
