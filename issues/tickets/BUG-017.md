# BUG-017: ウィンドウを閉じると最大 700ms 分の編集が保存されず消える

- **State**: Fixed
- **Reported**: 2026-08-02
- **Area**: app-shell（`titlebar.ts`）／ file-explorer（保存）

## Summary

自動保存は 700ms の debounce（`SAVE_DEBOUNCE_MS`）で走るが、ウィンドウを閉じる経路にフラッシュ処理がなかった。タイプ直後（700ms 以内）に ✕ ボタンや Alt+F4 で閉じると、debounce タイマー発火前に WebView ごと落ち、その入力が黙って失われる。

## Reproduction

1. ノートを開いて 1 文字入力する
2. 700ms 以内に ✕ ボタン（または Alt+F4）で閉じる
3. 再起動して同じノートを開く → 入力が無い

## Expected

閉じる操作の際に未保存の編集を確定してから終了する。

## Cause

`titlebar.ts:18` が `appWindow.close()` を直呼びしており、`onCloseRequested` / `beforeunload` 相当のフックがコード全体に存在しなかった（コードレビュー §1）。OS 側の閉じる操作も同様に素通り。

## Fix

`explorer/index.ts` の `initExplorer` で `getCurrentWindow().onCloseRequested` を購読し、`event.preventDefault()` → 現在ノートの内容を `flushSave()` で保存 → `appWindow.destroy()` で終了。`appWindow.close()` も OS 経由も `CloseRequested` を通るので 1 箇所で拾える。`capabilities/default.json` に `core:window:allow-destroy` を追加。

- **Fix commit**: `118e0a3`

## Notes

- 検証: ウィンドウのライフサイクルは開発機の headless では再現できないため、**Windows 実機での確認が必要**（タイプ直後の閉じる→再起動で編集が残ること）。
