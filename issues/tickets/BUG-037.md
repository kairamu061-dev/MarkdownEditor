# BUG-037: verify-build.bat が「( was unexpected at this time.」で止まる

- **State**: Fixed
- **Reported**: 2026-10-25
- **Area**: tooling（`scripts/verify-build.bat`）

## Summary

exe からユーザーフォルダのパスを除く変更（`0f40047`）のあと、`scripts\verify-build.bat` が
ビルドを始める前に構文エラーで止まる。

## Reproduction

1. 環境変数 `CARGO_HOME` を設定していない Windows（Rust の既定のインストール）で
2. `scripts\verify-build.bat bundle` を実行
3. `( was unexpected at this time.` と出て終了する

## Expected

`CARGO_HOME` の有無にかかわらずビルドが進む。

## Cause

追加した次の行。

```bat
if defined CARGO_HOME if "%CARGO_HOME: =%"=="%CARGO_HOME%" (
```

cmd は `if defined` を評価する**前に**、行（括弧のブロック全体）の `%...%` を展開する。
`CARGO_HOME` が未定義だと `%CARGO_HOME: =%` は空にならず、`%` の対応がずれて引用符が崩れ、
構文エラーになる。`CARGO_HOME` は通常は未定義なので、ほぼ全環境で起きる。
Windows で一度も実行せずに push したため、検証で初めて見つかった。

## Fix

判定を括弧のブロックや `if` の入れ子から、`goto` で 1 行ずつ分岐する形に書き換えた。
`CARGO_HOME` が未定義なら、`%CARGO_HOME: =%` を含む行には到達しない。

ビルド後の「exe にユーザーフォルダのパスが残っていないか」の確認も、同じ理由で括弧のブロックを
やめた（パスに `)` を含むとブロックが途中で閉じるため）。

開発機（Linux）には cmd が無く実行確認はできていない。Windows で確認する。

- **Fix commit**: a668415

## Notes

- 検証中の回避策: `CARGO_HOME` を `%USERPROFILE%\.cargo`（Cargo の既定の場所）と明示して実行。
  この方法で作った v0.4.1 の exe には、ユーザー名が 1 か所も残っていないことを確認済み
  （依存クレートのパスは `cargo-home\registry\...` に置き換わっている）
