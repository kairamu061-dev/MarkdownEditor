# BUG-034: 本文の先頭で Enter すると上の項目が `-` だけになり、箇条書きが解除される

- **State**: Fixed
- **Reported**: 2026-10-23
- **Area**: editor/live-preview（@codemirror/lang-markdown の `insertNewlineContinueMarkupCommand`）

## Summary

`- aaa` の `aaa` の先頭で Enter を押すと、上にできる空の項目が `-`（後ろの空白なし）になる。
そこにカーソルを合わせると `•` が `-` に戻り、続けて空白を打っても箇条書きに戻らず、
下の `• aaa` のインデントが崩れる。

## Reproduction

1. `- aaa` と入力（`• aaa` と表示される）
2. カーソルを `aaa` の先頭に置いて Enter → `•` / `• aaa`
3. 上の行にカーソルを合わせる → `-` / `• aaa`
4. `-` の後ろにスペースを入力 → 箇条書きにならず、下の `• aaa` の位置がずれる

観察（原文）:
```
-          ← 手順 2 の時点で、`-` の後ろの半角空白が消えている
- aaa
```

## Expected

上の行は `- `（空の項目）として残り、カーソルを乗せても `•` のまま。

## Cause

lang-markdown の Enter は、改行位置の**手前の空白を削る**。本文の先頭で押すと、
削られるのはマーク直後の空白なので、上の行が空白の無い `-` になる。

- `-` だけの項目では、カーソルをどこに置いてもマーク（`-` 1 文字）に触れるため、
  live-preview の規則どおりソース表示に戻る（手順 3）。ここまでは headless で再現・確認済み
- **手順 4（半角スペースを入れても箇条書きに戻らない）の原因は未確定。**
  開発機の headless Chromium では、修正前のコード・本番と同じ拡張・半角スペースで操作すると
  `- ` になって `•` に戻り、報告の症状は再現しなかった。報告どおりの表示（`-` が残り、
  下の `• aaa` がずれる）になったのは全角スペース（`-　`）を入れた場合だけだった。
  当初これを根拠に「IME で全角が入った」と推定したが、**報告者はすべて半角で入力しており、
  この推定は誤り**。WebView2 との差など、headless では見えない要因が残っている

## Fix

Enter のチェーンに `contentStartEnter` を追加した（`src/editor/live-preview.ts`）。
カーソルの左がマークと空白だけ、右に本文がある場合に限り、lang-markdown の改行を
そのまま実行し、**削られた空白だけを同じトランザクションで戻す**。
番号の振り直し・入れ子・引用の中のリストは lang-markdown の処理に乗ったまま。

実測（headless）:

| ケース | 修正前 | 修正後 |
|--------|--------|--------|
| `- \|aaa` ⏎ | `-\n- aaa` | `- \n- aaa`（↑ で乗っても `•` のまま） |
| `1. \|aaa\n2. bbb` ⏎ | `1.\n2. aaa\n3. bbb` | `1. \n2. aaa\n3. bbb` |
| `- x\n  - \|aaa` ⏎ | — | `- x\n  - \n  - aaa` |
| `> - \|aaa` ⏎ | — | `> - \n> - aaa` |
| 本文の途中・行末の ⏎ | — | 従来どおり（委譲） |

Ctrl+Z 1 回で元に戻る。

## Notes

- 2026-10-24: 報告者によると、発生したのは**普段とは別のマシン**。いつもの環境では手順 4 は再現しないとのこと。別マシンの詳しい情報が取れたら追記してもらう
- 修正で `-` だけの行ができなくなるので、通常の操作では手順 3・4 に入らない。ただし手順 4 の
  原因自体は未解明なので、Windows で「`-` だけの行の後ろに半角スペースを打つ」操作を
  別途確認してもらう（既存のノートや手入力で `-` だけの行は作れるため）
- 既存のノートにすでにある `-` だけの行は、カーソルを乗せると従来どおり `-` が見える
  （マークに触れているため・設計どおり）
