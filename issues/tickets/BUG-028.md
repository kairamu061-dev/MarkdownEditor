# BUG-028: 番号付きリストの最初の入力を日本語にすると、変換中の文字が一行下に出る

- **State**: Closed
- **Reported**: 2026-08-20
- **Area**: editor/live-preview（番号付きマーカーの幅固定と IME 変換）

## Summary

番号付きリスト（`1. `）の直後に日本語を入力すると、**変換中（未確定）の文字が
一行下に表示される**。変換を確定すると正しい位置に戻る。

箇条書き（`- `）では起きない。

## Reproduction

1. `1. ` と入力
2. 続けて日本語を入力（IME 変換中の状態にする）

観察: 未確定の文字が `1. ` の**次の行**に表示され、その行の高さが 2 行ぶんになる。
確定すると `1. ` の右隣に収まる。

## Expected

変換中も `1. ` の右隣に表示される。

## Cause

2026-08-20 に入れた番号付きマーカーの幅固定（`Decoration.mark` で
`display:inline-block; width: 文字数 × 1ch`）と IME の組み合わせ。

箱は `1. ` の範囲（マーク + 直後の空白）を覆う。カーソルはその箱の**末尾の境界**に
あるため、変換中の文字をブラウザが**箱の中のテキストノードに継ぎ足す**。

箱は幅が固定されているので、継ぎ足された文字が幅を超えると**箱の中で折り返す**。
これが「一行下に表示される」の正体。確定すると CodeMirror が描き直し、
文字が箱の外に出るため正しい位置に戻る。

実測（Chromium・CDP の `Input.imeSetComposition` で再現）:

```
入力直後   行の高さ 22   "1."@x42,y71 | " "@x55,y71
変換中     行の高さ 45   "1."@x42,y71 | " あ"@x55,y71 | " あ"@x42,y93   ← 箱の中で折り返している
確定後     行の高さ 22   "1."@x42,y71 | " "@x55,y71 | "あ"@x69,y71
```

箇条書きで起きないのは、弾丸がウィジェットへの**置換**であり、
変換中の文字が入る幅固定の箱が無いため。

## Fix

マーカーの箱に `white-space: pre` を足し、箱の中で折り返さないようにした
（`src/editor/live-preview.ts` の `markerBox`）。

変換中は文字が箱の右へはみ出す形になるが、そのときカーソルは行末にあり
後続の文字が無いため、見た目は正しい位置に並ぶ。確定時に箱の右端へ収まる際に
1 文字ぶんの微小なずれが出るが、行が飛ぶ現象は消える。

実測（修正後）:

```
変換中     行の高さ 22   "1."@x42,y71 | " あ"@x55,y71   ← 同じ行に収まる
```

- **Fix commit**: 69984e7

## Notes

- 検証は開発機の headless Chromium で、CDP の `Input.imeSetComposition` により
  実際の変換中状態を作って確認した。**実機の Windows IME でも 2026-08-21 にユーザーが確認し合格**
  （ここは外部要因が絡む唯一の項目のため、特に念入りに見てもらった）
- 幅を固定する箱は行頭空白にも使っているが、そちらは中身が空白のみで
  カーソルが末尾境界に来ないため、同じ問題は起きない
