# BUG-033: コードブロックの中でテキストを選択しても反転して見えない

- **State**: Fixed
- **Reported**: 2026-08-21
- **Area**: editor/code-highlight（`code-block.ts` の行背景）+ editor/core（`drawSelection`）

## Summary

コードブロックの行を選択しても、選択範囲のハイライトが**まったく見えない**。
通常の段落では見える。配色の問題ではなく**重なり順**の問題で、Nord・ライトの
どちらのプリセットでも起きる。

## Reproduction

1. コードブロックを含むノートを開く
2. コードブロックの中の行にカーソルを置き、Home → Shift+End で行を選択する

観察: 選択したはずの範囲の見た目が変わらない。通常の段落で同じ操作をすると
背景が変わる。

## Expected

通常の段落と同じように、選択範囲の背景色が変わる。

## Cause

CodeMirror の `drawSelection()` は選択範囲を自前のレイヤ
（`.cm-layer.cm-selectionLayer`）に描く。このレイヤは **`z-index: -2`**。

一方 `code-block.ts` の `.cm-codeblock-line` は行そのものに
`background-color` を掛けている。行要素は通常の重なり（`z-index: auto`）なので
**選択レイヤより手前に描かれ、選択のハイライトを覆い隠す**。

実測（headless Chromium・ライト配色）:

```
コードブロック行  選択レイヤ z-index -2、行の背景が手前 → 選択内と選択外のピクセルが同一
通常の段落行      行に背景が無い                     → 選択内と選択外のピクセルが異なる
```

重なり順が主因なので、**下地の色を変えるだけでは直らない**。

ただし修正の過程で、**色も条件のうち**だと分かった。重なり順を直しても、
Nord は下地（`--code-bg`）と選択色（`--bg-hover`）がどちらも `#434c5e` で
同じだったため、選択しても見た目が変わらないままだった。両方の対処が要る。

## Fix

**2 つ直す必要があった。重なり順だけでは足りない。**

### 1. 下地を選択レイヤより後ろに置く（`src/editor/code-block.ts`）

行そのものに掛けていた背景を擬似要素へ移した。

```
.cm-codeblock-line        { position: relative }
.cm-codeblock-line::before{ position: absolute; inset: 0; z-index: -3;
                            background-color: var(--code-bg) }
```

`position: relative` は `z-index: auto` のままなので**重ね合わせコンテキストを作らない**。
そのため `-3` は `.cm-scroller` のコンテキストで評価され、選択レイヤ（`-2`）の下に入る。
`.cm-codeblock-line` に `z-index` を足すと擬似要素がその中に閉じ込められ、効かなくなる。

### 2. 下地と選択の色を別にする（`src/settings/palette.ts`・`src/styles/nord.css`）

重なり順を直しても、Nord では `--code-bg` と `--bg-hover`（選択色）が
**どちらも `#434c5e` で同じ**だったため、選択しても見た目が変わらないままだった。
Nord の `--code-bg` を `#3b4252`（nord1）に変更した。

**これは既定の見た目が変わる変更**（コードブロックの下地が一段暗くなる）。
色が同じでは修正が成立しないため必要な変更と判断した。
ライトは元から別の色（下地 `#f0f2f5` / 選択 `#dfe3e8`）なので変更なし。

実測（headless Chromium・選択内と選択外の実ピクセル）:

| | 修正前 | 修正後 |
|---|---|---|
| Nord・コードブロック内 | 同一ピクセル（見えない） | 選択内 `67,76,94` / 選択外 `59,66,82`（差 12） |
| ライト・コードブロック内 | 同一ピクセル（見えない） | 選択内 `223,227,232` / 選択外 `240,242,245`（差 17） |
| 通常の段落（回帰確認） | 見える | 見える |
| コードブロックの下地 | あり | あり（消えていない） |

## Notes

- **以前から存在する。** 2026-08-21 に settings/theme の作業中、
  ライト配色でコード内の選択が見えるかを確認していて見つかった。
  Nord でも同じく見えないので、配色の変更で生まれた不具合ではない
- **インラインコード（`` `code` ``）と表の中のコードは直していない。** 同じ原因だが、
  span の背景が選択の帯の上に乗るだけで、行全体が覆われる訳ではなく可読性は保たれる
  （選択されていることは行の他の部分で分かる）。インライン要素は折り返しで
  分割されるため、絶対配置の擬似要素を敷くと**折り返しをまたぐ矩形が描かれる**恐れがあり、
  見た目の小さな改善に対して回帰の危険が大きいと判断した
- 影響は見た目のみ。選択・コピー・編集の動作そのものは元から正常
