# BUG-015: ウィキリンクが `[[note.md]]`（拡張子付き）・`[[sub/note]]`（サブフォルダ）で開けない

- **State**: Closed
- **Reported**: 2026-07-31
- **Area**: file-explorer（`openNoteByName`）

## Summary

`openNoteByName` が無条件に `.md` を補い、ファイル名単体（`node.name`）としか照合しないため、以下が解決に失敗する。
1. `[[note.md]]` → `note.md.md` を探して不一致
2. `[[sub/note]]` → サブフォルダ付き指定が `node.name`（`note.md`）と不一致

## Reproduction

1. 保管庫に `sub/note.md` を用意
2. 別ノートに `[[note.md]]` や `[[sub/note]]` と書いてクリック

観察: 「ノートが見つかりません」。拡張子なし・同一階層の `[[note]]` なら開ける。

## Expected

`[[note]]` / `[[note.md]]` / `[[sub/note]]` / `[[sub/note.md]]` のいずれでも該当ノートが開く。

## Cause

`src/explorer/index.ts` の `openNoteByName`（コードレビュー指摘 3.2）:
- `const wanted = \`${name}.md\`.toLowerCase();` が既に `.md` 付きの入力でも二重に付与。
- 照合が `node.name`（ファイル名単体）のみで、パス指定に対応していない。

## Fix

- 末尾が `.md` でない場合のみ `.md` を補完。
- 照合を `node.name` に加え `node.path`（区切りを `/` に正規化・小文字化）とも行う。ファイル名単体指定は従来どおり深さ優先で最初の一致、パス指定は完全一致で解決。

- **Fix commit**: `2ecbe00`

## Notes

- インラインリンク `[text](path)` は `main.ts` 側でファイル名へ簡約してから `openNoteByName` を呼ぶため主に影響するのはウィキリンク記法。
- コードレビュー（`tmp/コードレビュー結果.md` §3.2）由来。
- **2026-08-01 の Windows 実機検証（`26d72d7`）で `[[note.md]]`・`[[sub/note]]`・`[[sub/note.md]]`・`[[note]]` すべて解決を確認・合格** → Closed。
- 既知の付随挙動（不具合ではない）: 同名 `note.md` が複数階層に存在する場合、ファイル名のみ指定（バレ名）リンクの解決先はツリー走査順（ディレクトリ先行の深さ優先）に依存し、先に見つかった深い方に解決する。必要なら「同階層優先／最短パス優先」を別途 enhancement として検討（`docs/file-explorer/dev-notes.md` の今後の課題参照）。
