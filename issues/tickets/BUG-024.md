# BUG-024: アイコンを差し替えても exe のアイコンが更新されない

- **State**: Fixed
- **Reported**: 2026-08-04
- **Area**: tooling / src-tauri/build.rs

> **2026-08-04 追記（重要）**: 修正後も症状が続くとの報告を受けて Windows 側のビルド成果物を直接検査した結果、**exe には新しいアイコンが正しく埋め込まれていることを確認した**。残っている症状は Windows シェルのアイコンキャッシュによる表示上のもの。詳細は「検証結果」節。

## Summary

`src-tauri/icons/` を差し替えて再ビルドしても、生成された exe のファイルアイコン（エクスプローラ上の表示）が古いままになる。実行中アプリのタスクバーアイコンは更新される。

## Reproduction

1. `tauri icon` で `src-tauri/icons/` 一式を新しい絵柄に差し替える
2. `scripts\verify-build.bat` でリリースビルドする
3. 観測結果: タスクバーのアイコンは新しくなるが、`src-tauri\target\release\MarkdownEditor.exe` のアイコンは古いまま

## Expected

アイコンを差し替えて再ビルドしたら exe のアイコンも新しくなること。

## Cause

`tauri-build` は Windows 向けビルド時に `icons/icon.ico` を実行ファイルのリソース 32512 として埋め込む（`tauri-build-2.6.3` の `src/lib.rs:669` `res.set_icon_with_id(..., "32512")`）。

しかし `tauri-build` が `cargo:rerun-if-changed` を出しているのは `tauri.conf.json`・`frontendDist`・`capabilities`・`Info.plist` などであり、**アイコンファイル自体は対象外**（同クレート内を全数確認済み）。

Cargo はビルドスクリプトが宣言した入力が変化しない限り前回の出力を再利用するため、`icons/icon.ico` だけを差し替えても `build.rs` が再実行されず、古い `.res`（コンパイル済み Windows リソース）がそのままリンクされる。一方、実行中ウィンドウ／タスクバーのアイコンは別経路（`generate_context!` が埋め込むアプリ資産）から来るため更新される。この非対称性が症状の説明になる。

なお、Windows のシェルアイコンキャッシュが古い表示を保持している可能性も併存する（exe 自体は正しく更新されているのに古く見えるケース）。切り分け方は Notes 参照。

## Fix

`src-tauri/build.rs` に以下を追加し、アイコンディレクトリを明示的に監視対象にした。

```rust
println!("cargo:rerun-if-changed=icons");
```

ファイル単体（`icons/icon.ico`）ではなくディレクトリを指定することで、exe リソース用の `.ico` と `generate_context!` が読む PNG 群の両方をまとめてカバーする。パスはクレートルート基準で、`tauri.conf.json` の `bundle.icon` の基準と一致する。

`build.rs` 自体を編集するとビルドスクリプトのハッシュが変わるため、**この修正は次回ビルド時に自動で効く**（`cargo clean` は不要 = LTO のフルリビルドは発生しない）。

## 検証結果（2026-08-04）

作業ツリーは Windows の `D:\AI\Antigravity\MarkdownEditor` が devcontainer に `/workspaces/MarkdownEditor` としてマウントされたもので、`src-tauri/target/` も共有されている。そのため Windows 側のビルド成果物を devcontainer から直接検査できた。

| 検査対象 | 結果 |
|---------|------|
| `src-tauri/icons/icon.ico`（差し替え後） | 06:48:58 更新・64,927 bytes |
| `target/release/build/markdown-editor-29510d0555ddc088/out/resource.rc` | `32512 ICON "D:\AI\Antigravity\MarkdownEditor\src-tauri\icons\icon.ico"` を参照 |
| 同 `out/resource.lib`（コンパイル済みリソース） | 06:56:16 更新。**現行アイコンの 256px エントリのバイト列を含む**（完全一致） |
| `target/release/markdown-editor.exe` | 06:58 リンク。**現行アイコンの全 6 エントリ（16/24/32/48/64/256px）をバイト列として含む** |
| 同 exe に旧アイコン（`0daf6ac` のプレート案）のバイト列 | **含まれない** |
| 同 exe に初期 Tauri 既定アイコンのバイト列 | **含まれない** |

すなわち exe には新しいアイコンだけが正しく埋め込まれており、`build.rs` の修正は機能している。エクスプローラ上で古く見えるのは **Windows シェルのアイコンキャッシュ**による表示上の問題。

キャッシュが残りやすい条件が揃っている: exe は毎回同じパス（`src-tauri\target\release\markdown-editor.exe`）に出力され、シェルのアイコンキャッシュはパス単位で保持されるため、内容が変わっても再取得されないことがある。

### 表示を更新する方法

1. `ie4uinit.exe -show` を実行（Windows 10 / 11）
2. 効かない場合は `%LocalAppData%\Microsoft\Windows\Explorer\iconcache_*.db` を削除してエクスプローラを再起動
3. **キャッシュかどうかの切り分け**: exe を別名でコピー（`copy markdown-editor.exe test.exe`）してコピー側のアイコンを見る。新しいパスはキャッシュを経由しないため、正しいアイコンが出ればキャッシュ確定

## Notes

- **`build.rs` の修正が厳密に必要だったかは未確定**。`tauri-build` がアイコンに `rerun-if-changed` を出していないのはソース上の事実であり、修正自体は無条件に正しい。ただし今回の当初症状がリソース未再生成だったのか、最初からアイコンキャッシュだけだったのかは、当時の `resource.lib` が上書き済みのため事後判別できない。修正は保険として残す。
