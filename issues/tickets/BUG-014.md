# BUG-014: 保存失敗中にノートを切り替えると、失敗した内容で別ノートを誤上書きしうる

- **State**: Closed
- **Reported**: 2026-07-31
- **Area**: file-explorer（保存処理）

## Summary

`flushSave` が書き込みエラー時に編集内容を `pendingContent` へ戻すが、その間にユーザーが別ノートを開いていると `currentPath` は既に別ノートを指しており、次回保存で「元ノートの内容が別ノートに上書きされる」データ破損が起こりうる。

## Reproduction

（潜在バグ・write 失敗が前提）
1. `fileA.md` を編集（自動保存がスケジュールされる）
2. 保存の `write_note(fileA)` が権限/ロック等で失敗する状況で、失敗確定の前後に `fileB.md` を開く
3. その後の保存タイミングで `fileA` の編集内容が `fileB` に書き込まれる

## Expected

保存に失敗しても、その内容が別ノートに書き込まれない。

## Cause

`src/explorer/index.ts` の `flushSave` の catch が、保存対象 `path` と現在の `state.currentPath` の一致を確認せず無条件に `state.pendingContent = content` を実行していた（コードレビュー指摘 2.1）。保存中にノートが切り替わると、失敗内容が次のノートの保存内容として残る。

## Fix

catch 内で `state.currentPath === path` のときだけ `pendingContent` を復元するガードを追加。切り替わっていた場合は復元しない（別ノートの誤上書きを防止）。

- **Fix commit**: `2ecbe00`

## Notes

- 発火には `write_note` の失敗が必要なため実害頻度は低いが、起きるとデータ破損で影響大。修正は 1 行ガードで安価。
- コードレビュー（`tmp/コードレビュー結果.md` §2.1）由来。
- **検証は静的確認のみで Closed**: 実機で `write_note` の失敗（保存先ロック/読み取り専用）を安定して作れず動作確認はスキップ（2026-08-01）。ガード（`state.currentPath === path` のときだけ `pendingContent` を復元）はコード上で正しさを確認済み。将来、書き込み失敗を注入できる手段ができれば再確認する。
