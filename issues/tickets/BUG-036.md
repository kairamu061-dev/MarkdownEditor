# BUG-036: リネーム入力欄の中をクリックすると、打った文字がノート本文に入って保存される

- **State**: Open
- **Reported**: 2026-10-25
- **Area**: file-explorer/file-ops（`src/explorer/file-ops.ts` の `startRename`）

## Summary

右クリック → リネームの入力欄の中をクリックすると（カーソルを動かそうとして）、そのノートが開き、
入力欄が消えてフォーカスがエディタへ移る。続けて打った文字は**名前ではなく本文の先頭に入り、
自動保存される**。フォルダのリネームでは、入力欄の中をクリックするとフォルダが開閉する。

## Reproduction

1. ノートを右クリック → リネーム
2. 入力欄の途中をクリック → ノートが開き、入力欄が消える
3. `_` を打つ → ノート本文の先頭に `_` が入り、保存される

名前を変えてからクリックした場合は、blur でリネームが確定したうえで、同じく本文に文字が入る。

## Expected

入力欄の中のクリックはカーソル移動だけ。ノートは開かず、フォルダも開閉しない。

## Cause

入力欄は `row.replaceChildren(input)` で行の子として置かれる。入力欄の click がバブリングで
行の click ハンドラ（ノート = `openNote`、フォルダ = 開閉）まで届いていた。
file-ops の実装当初からある経路で、multi-select（`91daa63`）では行のハンドラに
`clearSelection()` が加わっただけ。

## Fix

`startRename` で、入力欄の `click` / `dblclick` の伝播を止めた。入力中は行の `draggable` も外し、
入力欄の文字をドラッグで選ぶ操作が行の移動として始まらないようにした
（確定・取消のどちらでもツリーは描き直されるので戻す処理は不要）。

headless（Tauri を偽装した保管庫）での実測:

| ケース | 修正前 | 修正後 |
|--------|--------|--------|
| ノートの入力欄をクリック → `_x` → Enter | ノートが開き、入力欄が消える | 入力欄にフォーカスが残り、`rename_path(メモA.md → メモA_x.md)` だけが呼ばれる。`write_note` なし |
| フォルダの入力欄をクリック・ダブルクリック | フォルダが開閉する | 開閉しない |
| 余白クリックでの確定（BUG-016・multi-select E-12） | 確定する | 同左 |
