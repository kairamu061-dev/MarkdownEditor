# BUG-027: リストの遅延継続行で Enter を押すと、入力した文字が消える

- **State**: Fixed
- **Reported**: 2026-08-20
- **Area**: editor/live-preview（@codemirror/lang-markdown の空項目判定）

## Summary

`- aaaa` → Enter → Enter → `a` → Enter と操作すると、入力した `a` が**消える**。
箇条書き・番号付きの両方で起きる。

## Reproduction

1. `- aaaa` と入力
2. Enter（新しい項目 `- ` ができる）
3. Enter（BUG-025 の修正でマークが消え、空行になる）
4. `a` と入力 → 画面上もディスク上も `- aaaa` / `a`
5. Enter

観察: `a` が消えて `- aaaa` だけが残る。

## Expected

`a` が残り、次の行にカーソルが移る。

## Cause

`insertNewlineContinueMarkup` の「空の項目か」の判定が、遅延継続行で誤爆する。

判定は `pos >= inner.to - spaceAfter && !/\S/.test(line.text.slice(inner.to))`。
`inner.to` は**マークの終わり桁**（`- ` なら 2）だが、遅延継続行にはマークが無いので
桁がずれる。行が `a`（1 文字）だと `"a".slice(2)` が `""` になり、
**中身があるのに「空の項目」と判定される**。

そのまま空項目の処理へ進み、`{ from: 行頭, to: カーソル, insert: "" }` が実行されて
行頭からカーソルまで、つまり入力した `a` が削除される。

### この経路を踏めるようにしたのは BUG-025 の修正

v0.3.0 では手順 3 の結果が `- aaaa` / 空行 / `- ` だったため、`a` は
`- a` という**マークのある行**になり、この判定には掛からなかった。

[BUG-025](./BUG-025.md) の修正で手順 3 が「マークを消して空行にする」に変わった結果、
**桁 0 の遅延継続行**という、誤爆する条件がちょうど揃うようになった。
lang-markdown 側の欠陥は以前から在ったが、**実用上の入口を作ったのはこちらの修正**。

なお v0.3.0 でも `- aaaa` → Enter → Backspace → `a` → Enter で近い状態は作れるが、
`deleteMarkupBackward` が 2 スペースの字下げを残すため行が `  a` になり、
`"  a".slice(2)` が `"a"` となって誤爆しない。

## Fix

`src/editor/live-preview.ts` の Enter バインドに `lazyListEnter` を追加し、
`quoteAwareEnter` → `lazyListEnter` → `markupEnter` の順で試すようにした。

`lazyListEnter` は次をすべて満たすときだけ素の改行（`insertNewline`）にする。

- カーソルが 1 つ・選択なし
- 行に非空白の文字が**ある**
- 行頭にリストマークが**無い**（＝遅延継続行）
- 属する項目の本文開始桁より右に文字が**無い**（＝誤爆する条件そのもの）

最後の条件で範囲を絞っているので、`  continued text` のように桁より右に本文がある
通常の継続行は従来どおり lang-markdown に渡る。

BUG-011 の `quoteAwareEnter`（引用の遅延継続行）とまったく同じ構図の問題で、
対処も同じ形にしてある。

実キー入力（Playwright）での確認:

| ケース | 修正前 | 修正後 |
|--------|--------|--------|
| `- aaaa` ⏎⏎ `a` ⏎ | `- aaaa\n`（**a が消える**） | `- aaaa\na\n` |
| `1. aaaa` ⏎⏎ `a` ⏎ | `1. aaaa\na\n` | 同左 |
| 桁より右に本文がある継続行 | `- item one\n    continued\n  ` | 同左（変化なし） |
| BUG-025 の各ケース | | すべて変化なし |
| 引用 3 ケース（E-15 含む） | | すべて変化なし |
