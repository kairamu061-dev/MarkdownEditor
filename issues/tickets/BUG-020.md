# BUG-020: `settings.json` の書き込みが非アトミックで、クラッシュ時に設定が消える

- **State**: Fixed
- **Reported**: 2026-08-02
- **Area**: file-explorer（`src-tauri/src/settings.rs`）

## Summary

`settings.rs` の `save` が `fs::write` の直書きで、`load` は破損 JSON を黙って `Settings::default()` にフォールバックする。書き込み中にプロセスが落ちると `settings.json` が壊れ、次回起動で `lastVault` と `recentVaults` 全件がエラー表示もなく消える（「保管庫を開く」画面に戻る）。

## Cause

`save`（`settings.rs:32-38`）が一時ファイルを介さず対象ファイルへ直接書き込み（コードレビュー §4）。寛容な `load` のフォールバック自体は「起動をブロックしない」設計として妥当なので、書き込み側で守るのが筋。

## Fix

一時ファイル（`settings.json.tmp`）へ書いてから `fs::rename` でアトミックに置換する定番対応。書き込み途中でクラッシュしても既存の `settings.json` は破損しない。

- **Fix commit**: `118e0a3`
