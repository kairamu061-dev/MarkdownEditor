# BUG-031: 空のリスト項目を Backspace で消すと、空白だけの行が残る

- **State**: Closed
- **Reported**: 2026-08-20
- **Area**: editor/live-preview（@codemirror/lang-markdown の `deleteMarkupBackward`）

## Summary

`- aaaa` → Enter で `- ` を出し、Backspace でそれを消すと、
**空白 2 つだけの行**が残る。カーソルも行頭に来ない。

## Reproduction

1. `- aaaa` と入力 → Enter（`- ` が自動で続く）
2. Backspace

観察（ディスク実内容）:
```
- aaaa
␣␣            ← 見えない空白 2 つが残る
```

## Expected

完全な空行になり、カーソルが行頭に来る。

## Cause

`deleteMarkupBackward` はマークだけを消し、**親項目の本文桁に合わせた空白**を残す。
入れ子の項目なら継続行として意味があるが、最上位の項目にはその空白の行き場が無い。

結果として、見えない空白がファイルに残り、カーソルも行頭に戻らなかった。

## Fix

`Prec.highest` の Backspace に `clearEmptyListItem` を追加した
（`src/editor/live-preview.ts`）。

行がマークだけ（`- ` `1. ` など、本文が空）で、カーソルが行末にあるときに限り、
**行のテキストをまとめて消して空行にする**。それ以外は従来どおりの削除に委譲する。

実測:

| ケース | 修正前 | 修正後 |
|--------|--------|--------|
| `- aaaa` ⏎ ⌫ | `- aaaa\n␣␣`（カーソル x=37） | `- aaaa\n`（カーソル x=29） |
| 入れ子で ⌫ | `- x\n␣␣` | `- x\n` |
| 空行に `- ` → ⌫ | `""` | 同左（変化なし） |

- **Fix commit**: 259d7c5

## Notes

- 報告では「先に消えるのは半角スペースのはずなので `-` が残るのが正しいのでは」と
  指摘があった。**マークを 1 文字ずつ消す形にはしていない。** `- ` をひとまとまりで
  消すのは「リストから抜ける」操作として一般的（Obsidian も同じ）で、
  実際の不具合は「消したあとに空白が残ること」だったと判断したため。
  1 文字ずつの削除に変えたい場合は言ってもらえれば差し替えられる
- 検証は開発機の headless Chromium。Windows / WebView2 は 2026-08-21 にユーザーが確認し合格
