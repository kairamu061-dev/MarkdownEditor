# BUG-038: タブを切り替えて戻ると、スクロール位置が最大 28px ずれる

- **State**: Fixed
- **Reported**: 2026-11-23
- **Area**: editor/tabs（`src/editor/index.ts` の `saveSession` / `restoreSession`）

## Summary

長いノートをスクロールしてから別のタブへ切り替えて戻ると、同じ行の画面上の位置が最大 28px ずれる。
ずれは積み重ならず、だいたいの位置には戻る（Windows 動作確認 E-06 の観察 1）。

## Reproduction

1. 長文ノートを開き、約 100 行スクロールする
2. 別のタブへ切り替え、元のタブへ戻る
3. 同じ行の画面上の位置が、切り替え前より 16〜28px 上下にずれている

## Expected

離れたときと同じ位置に戻る（spec「編集状態の保持」）。

## Cause

検証者の推定どおり。`saveSession` が `view.scrollDOM.scrollTop`（px）を保存し、`restoreSession` が
`setState` の次フレームでそれを書き戻していた。`setState` 直後の CodeMirror は、まだ描画していない行の高さを
推定値で持つ。推定値で並べた文書に同じ px を設定すると、上にある行の推定と実測の差だけずれる。
headless（見出し・折り返し段落の混ざった 400 段落）では数百 px ずれ、目的の行が画面外に出た。

## Fix

スクロール位置を `view.scrollSnapshot()` で保存し、`setState` の直後に明暗の reconfigure と同じ dispatch で流すようにした。
スナップショットは「先頭に見えている行とそこからのずれ」なので、行の高さの推定に左右されない。rAF も不要になった。

headless 実測（同じ行の画面上の位置、切り替え前 → 戻った後）:

| スクロール位置 | 修正前 | 修正後 |
|---------------|--------|--------|
| 3000px | 170 → -202（-372） | 170 → 169（-1） |
| 6100px | 行が画面外 | 170 → 170（0） |
| 9050px | 行が画面外 | 169 → 169（0） |
| 14000px | 行が画面外 | 214 → 214（0） |

### 追加修正（2026-11-24, `9d06686`）

Windows 確認（`d70f631`）で 51 回中 3 回、19px のずれが残った（いずれも下へスクロールした方向）。
headless でタブを開いた直後・ホイールでスクロールする条件にしたところ、32 回中 12 回 9px ずれる形で再現した。

スナップショットの記録は正しかった（例: 見出しの行 21、行の上端から 9px 下）。ずれは復元側で、
`setState` 直後は見えていない行の高さが推定値のため、1 回目の位置決めが推定の高さで行われる。
先頭に掛かった見出し（推定 22px・実測 31px）の差 9px が、実測後も残っていた。

次のフレーム（実測後）に同じスナップショットをもう一度当てるようにした。同じ条件で 32 回中 32 回 0px。
最初の実装では当て直しの判定を `view.state === session.state` にしており、直前の dispatch で state が
作り直されるため当て直しが一度も走っていなかった（doc の比較に変更）。

## Notes

- 検証者の推定: スクロール量（px）をそのまま戻しているが、`setState` 直後の CodeMirror は見えていない行の高さを推定値で持つため、実測との差だけずれる
