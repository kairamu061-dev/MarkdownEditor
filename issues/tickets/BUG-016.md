# BUG-016: リネーム入力を画面外クリック（blur）すると、入力した名前が黙って破棄される

- **State**: Closed
- **Reported**: 2026-07-31
- **Area**: file-explorer/file-ops

## Summary

ツリー項目のインラインリネーム中、Enter を押さずに画面外をクリックすると `blur` で無条件にキャンセルされ、入力した名前が確定されず破棄される。

## Reproduction

1. ノート/フォルダを右クリック→リネーム→新しい名前を入力
2. Enter を押さずにツリーの別の場所や画面外をクリック

観察: 変更が反映されず元の名前のまま（入力破棄）。

## Expected

blur 時に、妥当で変更のある名前なら確定する（一般的なインラインリネームの挙動）。

## Cause

`src/explorer/file-ops.ts` の `startRename` が `input` の `blur` に無条件で `cancel()` を割り当てていた（コードレビュー指摘 3.3）。加えて Enter の非同期確定（`confirm`）中に blur が追走して二重確定しうる懸念があった。

## Fix

- blur ハンドラを `commitFromBlur` に変更: 妥当（空でない・変更あり・`/` `\` を含まない）なら `confirm()` で確定、それ以外は `cancel()`。
- `submitting` フラグを追加し、`confirm` 実行中の再入（Enter と blur の二重確定）を防止。失敗時は `submitting` を戻して再入力可能に。

- **Fix commit**: `2ecbe00`

## Notes

- blur 確定でリネームが名前衝突で失敗した場合、入力は残り「同名の項目があります」を表示（次のツリー操作で再描画され解消）。UX 上の軽微な残余。
- 関連: [BUG-013](./BUG-013.md)（同じ `startRename`）。コードレビュー（`tmp/コードレビュー結果.md` §3.3）由来。
- **2026-08-01 の Windows 実機検証（`26d72d7`）で合格**（blur で確定・空/無変更は据え置き・blur 衝突はブロック）→ Closed。
