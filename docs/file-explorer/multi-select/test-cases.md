# file-explorer/multi-select テストケース

## E2Eテスト

ステータスの `[h]` は開発機の headless Chromium（Tauri の invoke を偽装した保管庫）で確認済み・Windows 未確認。

| ID | テスト名 | 前提条件 | 手順 | 期待結果 | ステータス |
|----|---------|---------|------|---------|-----------|
| E-01 | 範囲選択 | ルートにノート 4 件以上 | ノート名の右の空白から下へドラッグし、3 行に掛ける | 半透明の四角が出て、掛かった 3 件が選択色になる。離すと四角が消え、選択が残る。ノートは開かない | [h] |
| E-02 | ツリー下の余白から | ツリーの下に余白がある | 余白から上へドラッグしてノートに掛ける | 掛かったノートが選択される | [h] |
| E-03 | フォルダは選ばれない・開閉しない | フォルダとノートが混在 | フォルダ行を含むように範囲選択し、フォルダ行の上で離す | ノートだけが選択される。離した位置のフォルダは開閉しない | [h] |
| E-04 | Ctrl で追加 | 1 件選択済み | Ctrl を押しながら別の範囲を描く / Ctrl+クリック | 既存の選択に追加される。Ctrl+クリックは選択を切り替え、ノートは開かない | [h] |
| E-05 | 選択の解除 | 複数選択済み | (a) Esc (b) ツリー下の余白をクリック (c) ノートを普通にクリック | (a)(b) 全解除 (c) そのノートが開き、選択は全解除 | [h] |
| E-06 | まとめて移動 | 4 件選択済み | 選択中の 1 件の**名前**をフォルダ行へドラッグ | ドラッグ中に「4 件のノート」と表示される。4 件すべてがそのフォルダへ移り、移動後も選択されたまま | [h]（ドラッグ画像は未確認） |
| E-07 | 一部が同名 | 移動先に同名のノートがある | 同名を含む 2 件を選んで移動 | 移せる 1 件は移り、ステータス「同名の項目があるため 1 件は移動しませんでした」 | [h] |
| E-08 | 未選択の項目は単体移動 | 1 件選択済み | 選択されていないノートをドラッグ | そのノートだけが移り、選択は変わらない | [h] |
| E-09 | 範囲選択中の自動スクロール | ノートが画面に収まらない数ある | 範囲選択のままポインタをサイドバー下端へ寄せて止める | ツリーがスクロールし続け、四角が伸びて選択が増える | [h] |
| E-10 | 従来操作の非退行 | — | (a) 名前をドラッグしてフォルダへ移動 (b) フォルダ名クリックで開閉 (c) 行の右の空白を動かさずクリック | (a) 従来どおり移動 (b) 開閉 (c) ノートが開く / フォルダが開閉する | [h] |
| E-11 | 開いているノートを含む移動 | ノートを開いて本文を編集した直後（700ms 以内） | そのノートを含む選択をまとめて移動 | 編集内容が失われず、移動先のノートに残っている | [ ] |

## ステータス凡例

- `[ ]` 未実施
- `[h]` headless で確認済み（Windows 未確認）
- `[~]` 実施中
- `[x]` 合格
- `[!]` 不合格
