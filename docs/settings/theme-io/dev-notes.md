# settings/theme-io 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| **`settings/theme` の下（3 階層目）ではなく、`settings/` 直下の兄弟にした** | 内容としては `theme` にぶら下がるが、このリポジトリのサブ項目は**すべて 2 階層**で、3 階層目の前例が無い。依存関係（theme-io → theme）は親の `tasks.md` に書けば表現できる（`store → ui` と同じ形）。構造の前例を増やすより、既存の並びに合わせるほうが探しやすい |
| **これ以上サブ項目に分割しない**（spec.md 完了時に判定・2026-08-23） | UI 面は既存の配色セクションに 3 つボタンが増えるだけで独自の画面を持たない。エクスポートとインポートは同じファイル形式を共有していて、片方だけでは形式の検証ができない。並行作業の単位にもならない |
| **サブ項目にはした**（例外の 3 条件を通らなかった） | 追加するソースファイルが 1 つではない（`theme-io.ts` と `theme_io.rs`）。独自のスキーマを持つ（テーマファイルの形式と、`settings.json` の利用者テーマ一覧）。3 条件のうち 2 つで外れる |
| テーマファイルは**差分ではなく 23 項目すべて**を書き出す | 「Nord からの差分」にすると、受け取った側の Nord が将来変わったときに意味が変わる。配布物は自己完結でなければならない |
| テーマファイルに `dark` を持たせる | エディタの明暗は CSS 変数ではなく `EditorView.darkTheme`（CodeMirror の基底テーマ）で切り替えている。色だけ持っていっても、ライト系のテーマでエディタの既定スタイルが暗いままになる。組み込みプリセットが `Preset.dark` を持っているのと同じものが要る。**色の一覧だけ見ていると落とす項目** |
| 利用者テーマを `preset` に `user:<名前>` として入れる | `preset` は現在 `"nord" \| "light"` で、未知の値は Nord に落ちる。名前をそのまま入れると `nord` という名前のテーマが組み込みと衝突する。名前空間を分ければ、利用者がどんな名前を付けても衝突しない |
| 名前が重複したら上書きせず ` (2)` を足す | 黙って上書きすると、利用者が作り込んだテーマが消える。取り返しがつかない側に倒さない |
| **検証は TS 側だけに置く**（Rust は読み書きのみ） | 色の検証器（`isValidColor`）が `settings/theme` に既にある。Rust 側にも作ると 2 つの検証器がずれる。`settings/theme` で「未知のキー・不正な色を捨てる判断は TS 側に寄せる」と決めたのと同じ線 |
| `sanitizeOverrides` を取り込みに使い回さない | あれは「自分が書いた設定を黙って直す」ための関数で、不正な値を無言で捨てる。外から来たファイルに使うと、壊れたテーマが半分だけ適用されて原因が分からなくなる |
| **不正な色は拒否、足りない項目は補完**と扱いを分ける | 不正な値はファイルの作り手の誤りなので黙って直すべきではない。足りない項目は、こちらが将来 24 項目目を足したときに**古いテーマファイルが全部読めなくなる**のを避けるため。補ったら件数を伝える |
| **エクスポートしたファイルはモーダルのキャンセルで消さない** | ファイルの書き出しは外向きの・取り消せない操作。モーダルの「キャンセル」は画面の配色を戻すためのもので、既に書いたファイルまで責任範囲に含めると挙動が読みにくい |

## 発生した問題と対処

| 問題 | 対処 |
|------|------|
| Nord を選んだままエクスポートすると名前が `Nord（ダーク）` になり、取り込むと**選択欄に同じラベルが 2 つ並ぶ** | `uniqueName` の突き合わせ先が利用者テーマ同士だけだった。**選択欄に並んでいるラベル全部**（組み込みを含む）に変更。内部的には `nord` と `user:Nord（ダーク）` で別物なので動作は正しかったが、表示で見分けが付かなかった |
| エクスポートをキャンセルすると、直前の「書き出しました」が残って成功したように見える | `exportButton` が `clearNotice()` を呼んでいなかった。エクスポート・インポートとも、押した時点で前の通知を消すようにした |
| 不正な色を「テーマファイルの**形式**が正しくありません」と言っていた | 形式は正しく、色の値だけが不正なので不正確だった。「テーマファイルの**色の指定**が正しくありません」に変更し、設定画面の 16 進入力欄と言い回しを揃えた。spec.md も 1 対 1 で更新 |

3 件とも 2026-08-23 の Windows 検証の所感で挙がったもの。「不具合ではない」という
整理だったが、**2 件は実装側の取りこぼし**だったため修正した。

## 今後の課題

- **元ファイルの変更に追従しない。** 取り込んだ時点の内容が `settings.json` に入るので、
  配布元のファイルを直しても反映されない。取り込み直す必要がある
- **利用者テーマの名前は変更できない。** 作り直せば済むと判断した
- テーマ数の上限を設けていない。増えると `settings.json` が大きくなる
  （1 テーマあたり 23 色 ≒ 700 バイト程度なので、実用上は問題にならない見込み）
- `UserTheme` の**型そのものが違う**設定ファイル（`colors` が文字列など）を読むと、
  `theme` 全体が既定に落ちる。既存フィールドと同じ性質なのでここだけ強くはしていない
