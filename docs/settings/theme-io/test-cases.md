## 検証記録

**2026-08-23 の Windows 検証（`0f3c73e` 相当のビルド）で E-20〜E-37 を全項目合格とした。**
実施したのは Windows 側の自動化セッションで、ユーザーが結果を確認した。

開発機で模擬していた**実機のネイティブファイルダイアログを実操作**して確認している —
保存ダイアログの既定ファイル名（`Nord（ダーク）.json`・全角括弧はそのまま）、
`.json` のフィルタ、Esc でのキャンセルが no-op になること。

E-34（明暗のフリップ）は目視ではなく**同一位置のピクセル A/B 比較**で確認された。
組み込みライトと、それを書き出して取り込み直したテーマが、エディタ背景・サイドバー・
コード下地・コードブロック内の選択のいずれも**ピクセル単位で一致**した。

E-35 は「見た目が戻る」だけでなく、**上書きの ● が 1 つも出ない**ことまで見ている。
色がテーマの 23 色に焼き込まれ、`draft.colors` が空のまま同じ見た目になる
＝自己完結した形式にした狙いどおり。

先行して開発機の headless Chromium でも I-02〜I-08 と E-20〜E-33 相当を確認済み
（`invoke` を差し替えてダイアログを模擬）。

### 検証後の指摘 3 件の修正（2026-08-23・E-38 / E-39）

Windows 検証の所感で挙がった 3 点を直した。いずれも不具合ではないという整理だったが、
2 件は実装側の取りこぼしだったため修正した。

1. **組み込みラベルと同名の利用者テーマができる** — `uniqueName` の突き合わせ先が
   利用者テーマ同士だけだった。**選択欄に並んでいるラベル全部**（組み込みを含む）に
   変更。Nord を書き出して取り込むと `Nord（ダーク） (2)` になる（E-38）
2. **エクスポートをキャンセルすると古い通知が残る** — `exportButton` が
   `clearNotice()` を呼んでいなかった。インポート側も含めて、押した時点で消すようにした（E-39）
3. **不正な色のメッセージの言い回し** — 「テーマファイルの**形式**が正しくありません
   （text: abc）」は、形式は正しく色の値だけが不正なので不正確だった。
   「テーマファイルの**色の指定**が正しくありません（text: abc）」に変更し、
   設定画面の 16 進入力欄（「色の指定が正しくありません」）と揃えた。spec.md も更新

E-38 / E-39 は開発機で確認済み。**Windows / WebView2 は未確認のため `[~]`。**

I-07（往復の一致）は、書き出したファイルをまっさらな設定に取り込み直して
23 色と `dark` が一致することに加え、**実際に適用して描画したスクリーンショットが
バイト一致する**ことまで確認している。

E-34（ライト系テーマの明暗）は、テーマファイルに `dark` を持たせた理由そのもの。
色だけ持っていくと、エディタの基底スタイル（`EditorView.darkTheme`）が
暗いままになる。**色の一覧だけ見ていると落とす項目**なので、実機で必ず見ること。
