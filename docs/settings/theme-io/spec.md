# settings/theme-io 仕様

## 機能一覧

| # | 機能名 | 説明 |
|---|--------|------|
| 1 | エクスポート | 今画面に見えている配色を、名前付きの JSON ファイルに書き出す |
| 2 | インポート | JSON ファイルを読み、利用者テーマとして登録する |
| 3 | 利用者テーマの選択 | 組み込みプリセットと並んで選択欄に出る。切り替えで即反映 |
| 4 | 削除 | 選択中の利用者テーマを一覧から消す |
| 5 | 永続化 | 利用者テーマを `settings.json` に保存し、起動時に読み込む |

## テーマファイルの形式

拡張子は `.json`。**23 項目すべてを持つ自己完結した形式**にする。

```json
{
  "format": "markdown-editor-theme",
  "version": 1,
  "name": "Solarized",
  "dark": true,
  "colors": {
    "bgPrimary": "#002b36",
    "bgSidebar": "#073642",
    "...": "（settings/theme の spec.md にある 23 項目すべて）"
  }
}
```

| フィールド | 必須 | 説明 |
|-----------|------|------|
| `format` | ○ | 固定値 `markdown-editor-theme`。他の JSON を誤って読まないための印 |
| `version` | ○ | 形式のバージョン。現在は `1` |
| `name` | ○ | 一覧に出る名前。空文字は不可 |
| `dark` | ○ | 明暗。`true` ならエディタの基底スタイルが暗い側になる |
| `colors` | ○ | 項目名 → `#rrggbb`。項目名は `settings/theme` の `ColorKey` |

**「Nord からの差分」にはしない。** 受け取った側の Nord が将来変われば意味が変わるため、
必ず 23 項目を実際の色で書き出す。

### `dark` が要る理由

エディタの明暗は CSS 変数ではなく `EditorView.darkTheme`（CodeMirror の基底テーマ）で
切り替えている。色だけ持っていても、ライト系のテーマを取り込んだときに
エディタの既定スタイルが暗いままになる。組み込みプリセットが持っている
`Preset.dark` と同じものを、利用者テーマも持つ必要がある。

## 利用者テーマの識別

**組み込みプリセットとは別の名前空間に置く。** 現在 `theme.preset` は
`"nord" | "light"` の文字列で、未知の値は Nord に落ちる仕様。ここに利用者テーマの
名前をそのまま入れると、`nord` という名前のテーマを作られたときに衝突する。

利用者テーマは `preset` に **`user:<名前>`** の形で入れる。

| `theme.preset` の値 | 意味 |
|--------------------|------|
| `null` / `"nord"` | 組み込みの Nord |
| `"light"` | 組み込みのライト |
| `"user:Solarized"` | 利用者テーマ `Solarized` |
| その他・存在しない利用者テーマ | Nord に落ちる（既存の仕様どおり） |

この形なら、利用者が `nord` という名前を付けても衝突しない。

## 画面・操作フロー

### エクスポート

1. 設定モーダルを開き、配色を好きな状態にする（プリセット選択や項目の上書き）
2. 「エクスポート」を押す
3. 保存ダイアログが出る。既定のファイル名は現在のテーマ名（例 `Nord（ダーク）.json`）
4. 保存すると、**そのとき画面に見えている 23 色**が書き出される

エクスポート・インポートを押した時点で、**前回の通知は消える。**
消さないと、キャンセルしたときに直前の「書き出しました」が残って
成功したように見える。

**保存前のプレビュー状態を書き出す。** モーダルで色をいじって保存していなくても、
見えているとおりの色が出る（「変更含めてエクスポート」という要望のとおり）。
書き出したあとキャンセルで閉じても、**ファイルはそのまま残る**（画面の配色だけが戻る）。

### インポート

1. 「インポート」を押す
2. ファイル選択ダイアログが出る（`.json` を絞り込み）
3. 選ぶと検証され、通れば利用者テーマとして登録される
4. **登録した直後にそのテーマへ切り替わる**（プレビュー）
5. 「保存」で確定。キャンセルすると**登録も取り消される**

### 削除

1. 利用者テーマを選んでいるとき、「このテーマを削除」が出る
2. 押すと一覧から消え、**Nord に切り替わる**
3. 「保存」で確定。キャンセルすると削除も取り消される

## 各画面 / 状態の詳細

### プリセットの選択欄

組み込み 2 つ → 利用者テーマ（登録順）の順に並べる。
利用者テーマは名前をそのまま表示する。

### ボタンの表示条件

| ボタン | 表示条件 |
|--------|---------|
| エクスポート | 常に |
| インポート | 常に |
| このテーマを削除 | **利用者テーマを選んでいるときだけ** |

### 名前が重複したとき

同じ名前が既にある場合、**上書きせず名前の後ろに ` (2)` を足す**
（`Solarized` → `Solarized (2)` → `Solarized (3)`）。
黙って上書きすると、利用者が作り込んだテーマが消える。

**突き合わせ先は「そのとき選択欄に並んでいるラベル全部」**で、利用者テーマ同士だけでは
ない。組み込みプリセットも含める — Nord を選んだ状態でエクスポートすると名前が
`Nord（ダーク）` になり、それを取り込むと**同じラベルが 2 つ並んで見分けが付かなくなる**
（内部的には `nord` と `user:Nord（ダーク）` で別物なので動作は正しいが、表示が紛らわしい）。

## エラーケース

| 条件 | メッセージ / 挙動 |
|------|------------------|
| ファイル選択・保存をキャンセルした | 何も起きない（エラーではない） |
| ファイルが読めない（権限・消えている） | 「ファイルを読み込めませんでした」 |
| JSON として壊れている | 「テーマファイルの形式が正しくありません」 |
| `format` が違う / 無い | 「このファイルはテーマファイルではありません」 |
| `version` が未知（2 以上） | 「このテーマファイルは新しいバージョンです」 |
| `name` が無い / 空 | 「テーマファイルの形式が正しくありません」 |
| `colors` に**不正な色の値**が入っている | 「テーマファイルの色の指定が正しくありません（`text`: `abc`）」として**取り込まない**。形式そのものは正しいので「形式」とは言わない。設定画面の 16 進入力欄のメッセージと言い回しを揃えている |
| `colors` に**知らない項目名**が入っている | その項目を捨てて取り込む（将来の項目削除に耐えるため） |
| `colors` に**足りない項目**がある | `dark` に応じて Nord / ライトの色で埋めて取り込み、「N 項目を既定値で補いました」と表示 |
| 書き出しに失敗した | 「テーマの書き出しに失敗しました」 |
| 保存に失敗した | 既存と同じく「設定の保存に失敗しました」 |

**不正な値は拒否、足りない項目は補完**と、扱いを分けている。不正な値はファイルの
作り手の誤りなので黙って直すべきではない。足りない項目は、こちらが将来項目を
増やしたときに**古いテーマファイルが全部読めなくなる**のを避けるため。

## 未対応ケース

- **オンラインからの取得・配布**。ローカルのファイル入出力のみ
- **組み込みプリセットの書き換え・削除**
- **利用者テーマの名前の変更**。作り直せば済む
- **元ファイルの変更に追従すること**。取り込んだ時点の内容を `settings.json` に持つ
- **フォルダ指定での一括取り込み**
- **配色以外の入出力**（フォント・寸法・キーバインド）
- **テーマ数の上限**。設けない（`settings.json` が大きくなるだけ）
- **同じ内容のテーマの重複検知**。名前が違えば別物として登録する
