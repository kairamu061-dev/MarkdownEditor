# settings/theme 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| **これ以上サブ項目に分割しない**（spec.md 完了時に判定・2026-08-21） | 分割条件を 4 つとも満たさない。UI 面は `settings/ui` の既存モーダルの中の 1 セクションで独自の画面ではない。スキーマは 23 項目のカラーマップ 1 つで、パレット定義・適用・UI で共有する。パレット定義だけを切り出しても、適用先が無いと動作を確認できず単独でテストできない。並行作業の単位にもならない |
| 設定項目を 23 個にした（見出し 1〜6 を個別に） | 2026-08-21 にユーザーが「見出し 1〜6 を個別に」を選択。8 項目案（見出しは 1 色）も提示したうえでの選択 |
| プリセットの色も毎回 23 項目すべて明示的に設定する | `nord.css` の既定値に頼って「Nord のときは何も設定しない」とすると、ライト → Nord に戻すときに `removeProperty` の取りこぼしで一部だけライトの色が残る事故が起きやすい。常に全部書けばこの経路が消える |
| `colors` を Rust 側で enum にせず `BTreeMap<String, String>` にする | 項目を将来増減したとき、古い `settings.json` でデシリアライズが失敗すると `theme` 全体が既定に落ちて**利用者の配色が丸ごと消える**。未知キーを捨てる判断は TS 側に寄せる。`BTreeMap` はキー順が安定するので保存のたびに差分が出ない |
| 引用の設定項目を 1 つ（バー色）にし、本文色と背景を導出する | 引用は左バー・本文・背景の 3 色で「引用らしさ」を出しているが、3 項目に増やすと設定画面が長くなるうえ、3 色の関係を利用者が壊せてしまう |
| コード専用の設定項目を 6 種（色 5 + 下地 1）に絞る | 関数名・演算子・変数名まで別項目にすると項目が増えすぎる。関数名はアクセント、演算子は第 2 アクセント、変数名は文字色に従わせても実用上困らない |
| `--code-bg` を `--bg-hover` から分けた（23 項目目） | コードの下地と「選択・ホバー背景」が同じ変数だった。役割が違うので、利用者が選択色を調整するとコードブロックの下地まで変わってしまう。Nord では両方とも暗くて気づかないが、明るい配色では致命的。Nord プリセットの値は分離前と同じ `#434c5e` にして既定の見た目を保った |
| ライト/ダークの切り替えを `EditorView.darkTheme` ファセット + `Compartment` で行う | `EditorView.theme(spec, { dark })` の `dark` はこのファセットを立てているだけなので、ファセットだけ差し替えればテーマ定義を作り直さずに済む。テーマ本体は CSS 変数を参照しているため、色は変数の更新だけで追従する |
| プリセットを切り替えたら項目ごとの上書きは全部捨てる | Nord で背景を黒く上書きした人がライトへ切り替えると、背景は黒のまま文字だけライトの黒になり画面が読めなくなる。`--bg-sidebar` を上書きしていれば設定モーダルごと読めなくなり、「すべて初期値に戻す」も押せない。コントラスト比の検証を未対応にしているのは「いつでも戻せる」前提の上なので、その前提を壊す挙動は採らない |
| **画面に出る色はすべて 23 項目のどれかに辿り着く**ことを要件にした | 項目に属さない色が 1 つでも残ると、全項目を変えてもそこだけ Nord の色が残る。`--accent-secondary`（演算子・テーブル見出し）と `--syntax-mark`（記法の印・スクロールバー）は当初 8 項目案では拾えておらず、ライトテーマで浮くところだった。`grep` で `--nordN` の直接参照が 0 件になっても、**項目に属さないエイリアスは検出できない**ので、要件として書いておく |
| `--warning` / `--success` は設定項目にしない | 見出し 1・見出し 2・コードの文字列から専用変数へ張り替えると、参照が 0 件になる。画面に出ない色を設定画面に並べても混乱するだけ。将来ステータス表示で使う余地があるので `nord.css` からは消さない |
| ライトの見出し 1（`#b58900`）とコメント（`#7a8494`）を**そのままにした** | 2026-08-22 の Windows 検証で「他より淡い」と所感があり、実測でも白背景に対して 3.21:1 / 3.37:1 と、兄弟項目（見出し 2〜6 は 4.92〜5.30）より低い。`#8a6a00` / `#5f6b7d` にすれば揃うことも確認済み。ただし**ユーザーが現状維持を選択**（2026-08-22）— 読めないレベルではなく、気になれば設定画面で各自変えられる（それがこの機能の目的）ため。変えるなら `palette.ts` の `light.colors` の 2 行だけで、Nord には影響しない |
| `subscribeDark` は登録時に現在値で 1 回呼ぶ | `initSettings()` が `mountEditor()` より先に走るため、単純なイベント通知だと起動直後の 1 回を取りこぼす。順序依存を仕様で消す |

## 発生した問題と対処

| 問題 | 対処 |
|------|------|
| 見出しの色が用途別エイリアスを共有していて単独で変えられない（H1=`--warning`、H4=`--accent` など）。H4 を変えるとカーソル・リンク・リストの弾丸まで変わる | `--heading1`〜`--heading6` を新設し、既定値を現在の色と同じにする。用途別エイリアスは「同じ意味の色をまとめる」ためのもので、「利用者の調整口」としては粒度が合っていなかった |
| `--comment` / `--quote-text` / `--quote-bg` が `color-mix()` で `--nord4` `--nord3` `--nord9` から計算されており、エイリアスを上書きしても追従しない | `--comment` は `--code-comment` に統合して混合をやめる。引用の 2 つは混合元を `--text` / `--border` / `--quote-bar` に張り替える |
| `--nordN` を直接参照している箇所が 4 つあり、上書きしてもそこだけ Nord のまま残る（`editor/theme.ts` に 3 つ、`app.css` に 1 つ） | 新変数・エイリアスへ差し替える。`grep -rn "var(--nord" src/ \| grep -v styles/nord.css` が空になることを検査項目にした |

## 設計からの変更点

| 変更内容 | 理由 |
|----------|------|
| `--code-comment` を「固定値」ではなく `color-mix(var(--text) 40%, var(--border))` のままにした | 設計時は「上書きできるように混合をやめて固定値にする」と書いたが、不要だった。`documentElement` へのインライン設定は `:root` の規則に優先するので、既定値が `color-mix()` でも上書きは効く。しかも混合元をエイリアスにしておけば、文字色を変えたときにコメント色も自然に追従する。実効値は変更前と同じ `#848c9d` |

## 実装の検証記録

### 1. 変数の整備（2026-08-21）

**「見た目が 1 ピクセルも変わらない」を実測で確認した。** 変更前（`git archive HEAD`）と
変更後の `src/` をそれぞれ headless Chromium でバンドルして描画し、比較した。

- **スクリーンショット: バイト一致**（見出し 1〜6・コードブロック・引用・テーブル・
  リンク・強調・打ち消しを含む文書で比較）
- **描画された 56 要素の文字色・背景色・文字サイズ: 全て一致**
- **CSS 変数の実効値**: 差分は 12 件で、すべて意図どおり
  - 新設した 11 変数（`--heading1`〜`6`・`--code-*`）— 変更前は未定義で継承色になっていた
  - `--comment` — `--code-comment` へ改名したので変更後は未定義
  - `--code-comment` の実効値は、変更前の `--comment` と**同一**
    （`color(srgb 0.517647 0.550588 0.614902)` = `#848c9d`）
- `--nordN` の直接参照: 4 件 → **0 件**
- `src/` で参照されている色変数は 26 個で、**当時の 22 項目 + 導出 4 個**にちょうど一致した
  （その後 `--code-bg` を足して 23 項目 + 導出 4 個 = 27 個になり、再照合で一致を確認済み）

### 5. Windows 実機検証（2026-08-22）

`c497ff7` 相当のビルドで E-01〜E-18 が全項目合格。詳細は test-cases.md の検証記録。
実機でしか見られなかったのは E-11（ライト配色の全 UI 面）で、サイドバー・ツリー・
タイトルバー・保管庫スイッチャ・設定モーダル・右クリックメニュー・スクロールバー・
エラートーストまで可読と確認された。

**検証中にアプリが 1 回だけ予期せず終了した**が、本機能起因ではないと判断した。
保管庫の切り替えはエディタを再マウントするので `subscribeDark` →
`EditorView.darkTheme` の reconfigure が走る箇所であり、疑う理由はあった。切り分け:

- `%LOCALAPPDATA%\CrashDumps` に `markdown-editor.exe` のダンプ無し。
  Application ログにも Application Error（Id 1000）無し
- 同時刻帯の WER はすべて `BlueScreen` / `LiveKernelEvent`
  （`VIDEO_TDR_ERROR`＝GPU タイムアウト/リセット、`DRIVER_POWER_STATE_FAILURE`）。
  WebView2 は GPU 合成なので、GPU の TDR リセットでウィンドウが落ちるのは
  アプリのロジックと無関係に起こりうる
- ライト保存状態で保管庫を 14 サイクル（切り替え 28 回）試したが**再現せず**

再発するようなら GPU ドライバ側を疑うこと。**記録として残す。**

### 6. BUG-033 の修正と Windows 検証（2026-08-22）

コードブロック内の選択が見えない件を修正し、実機で合格。詳細は
[BUG-033](../../../issues/tickets/BUG-033.md) と test-cases.md の E-19。

修正で分かった**残る 2 点**（どちらも不具合ではない）:

- **Nord のコードブロック内の選択は、他の場所より弱い。** 選択色（`#434c5e`）と
  コードの下地（`#3b4252`）の差は 12。コードブロックの外は背景（`#2e3440`）との差が
  30 あるので、体感では明らかに差がある。「見えない」からは脱したが「くっきり」ではない。
  原因は、選択色と背景色が元々 30 しか離れておらず、**下地はその間に入れるしかない**こと。
  強くするなら選択色（`--bg-hover`）を `#4c566a`（nord3）へ上げるのが唯一まともな手
  （背景との差 42・下地との差 24 で両方改善する）。下地をさらに暗くする案は、
  背景との差が 9 以下になってコードブロックの範囲が分からなくなるので**採れない**
- **`--code-bg` はインラインコード・表の中のコードとも共有している。** Nord の値を
  `#434c5e` → `#3b4252` に変えたことで、インラインコードのピルと本文背景の差も
  30 → 18 に縮んだ。判別はできるが以前より淡い。**チェックリストではコードブロックしか
  説明しておらず、この波及を伝えそびれた**（実装時から共有は分かっていた）。
  分けたい場合はインライン用の変数を新設して 24 項目目にする

**この 2 点は現状維持をユーザーが選択（2026-08-22）。** どちらも「見えない」レベルでは
なく、気になれば設定画面で各自変えられるため。**良かれと思って直さないこと** —
変えるなら上に書いた手段（選択色を nord3 へ / インライン用の変数を新設）を使う。

## 今後の課題

- **ライトテーマは色の差し替えだけでは完成しない。** 暗い背景を前提にした境界線の濃さ、
  選択範囲の見え方、スクロールバー、コードブロックの背景が、明るい下地では
  コントラストが足りない可能性がある。実装時に目視で詰める
- **コントラスト比の検証は行わない。** 背景と文字を同じ色にすることも止めない。
  「すべて初期値に戻す」で復旧できることを逃げ道にしている。設定画面の外
  （たとえばコマンドパレット）から復旧する手段は用意していない
- 配色セットのファイル入出力（テーマの配布）は未対応。要望があれば
  `ThemeSettings` をそのまま JSON に書き出す形で足せる
- **[BUG-033] コードブロック内の選択が見えない** — `--code-bg` を分けたときに
  ライト配色で確認していて見つけた。`drawSelection()` の選択レイヤが `z-index: -2` で、
  `.cm-codeblock-line` の行背景がその手前に描かれて覆い隠している。
  **色の問題ではないので `--code-bg` の分離では直らない**（Nord でも同じく見えない）。
  以前から存在する不具合で、`editor/code-highlight` と `editor/core` に
  またがるため配色の作業とは分けて対応する
