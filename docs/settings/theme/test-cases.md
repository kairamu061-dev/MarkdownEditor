## 検証記録

**2026-08-22 の Windows 検証（`c497ff7` 相当のビルド）で E-01〜E-18 を全項目合格とした。**
実施したのは**ユーザー本人ではなく Windows 側の自動化セッション**で、実機
（Windows 11 / WebView2）を `scripts\verify-build.bat` で再ビルドして起動し、
UI Automation・スクリーンショットの目視・`settings.json` のバイト照合で確認している
（結果は `tmp/フィードバック/old/` に保管）。ユーザーがその報告を確認し、
問題なしと判断した。

実機でしか見られなかった部分の結果:

- E-11 は**全 UI 面**（サイドバー・ツリー・タイトルバー・保管庫スイッチャ・
  設定モーダル・右クリックメニュー・スクロールバー・エラートースト）で可読性を確認。
  コントラスト不足の箇所は見つからなかった
- E-18 は `theme.colors` に**変更した 1 項目だけ**が入り、全 23 項目が
  書き込まれていないことをバイト照合で確認
- E-04 のネイティブカラーピッカーは「出ること」だけ確認し、色の変更は 16 進欄経由で
  行っている（どちらも同じ `set()` → `preview()` を通るため経路は同一）

以下は 2026-08-21 に開発機の headless Chromium で先行確認したもの
（項目数 23・グループの開閉・即時プレビュー・上書き印・キャンセル復元・保存・
プリセット切り替えでの上書き破棄・入力途中の値を保存で弾く・色見本の実描画色）。
プリセット解決と上書きの取捨も、未知のプリセット名／未知の項目名／不正な色値を
含めて確認済み。

E-11（ライト配色の見え方）は headless では**エディタ本文しか描画していない**ため
実機での確認が必要だったが、上記の Windows 検証で全 UI 面を確認済み。

E-19（BUG-033）は 2026-08-22 に修正し、開発機の headless Chromium で
選択内と選択外の**実ピクセル**を読んで確認した（Nord 差 12・ライト差 17、
修正前はどちらも同一ピクセル）。下地が消えていないこと、通常の段落の選択が
壊れていないことも同時に確認済み。**Windows / WebView2 は未確認のため `[~]`。**
