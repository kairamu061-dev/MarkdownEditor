# editor/live-preview 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| 表示切り替えを Decoration.replace のみで実装（文書は不変更） | undo 履歴や保存内容に影響を与えないため。CodeMirror の標準機構で軽量 |
| 走査対象を view.visibleRanges に限定 | 大きな文書でも選択移動のたびの再計算を軽く保つ（省メモリ・軽快さ方針） |
| 引用の装飾判定は Blockquote ノードではなく QuoteMark 単位 | 2026-07-24 のフィードバック「行頭が `>` でない行は引用扱いしたくない」への対応。CommonMark の遅延継続（lazy continuation）では `>` の無い行も `Blockquote` ノードに含まれるため、ノード単位で装飾すると `>` を消した行まで引用のままになる。実際に `>` がある行だけに `QuoteMark` が付く（パーサで確認）ので、QuoteMark を基準にすれば「行頭が `>` の行」だけを引用にできる |
| 引用マーク `>` は隠す（ただしカーソルのある行はソース表示） | 2026-07-24 のフィードバック「`>` の見た目を消したい」への対応。他の記法マークと同じく `touchesSelection`（行単位）で、カーソルがその行にある間だけ `>`（＋直後の空白）をソース表示し、それ以外は replace で隠す。BUG-010（`deleteMarkupBackward`＋IME）は依存更新（`a8326d2`）で解消済み。かつ hide されるのは非アクティブ行のみ（編集中の行の `>` は表示）なので、編集・IME 中の行に replace 装飾は載らない |

## 設計からの変更点

| 変更内容 | 理由 |
|----------|------|
| テーブルレンダリングを `table-preview.ts` として live-preview.ts から分離して追加（2026-07-13） | GFM テーブルがソーステキスト表示のまま「記法が動作していない」とのユーザーフィードバック。シンタックスハイライト（`\|` の色変更）のみでは視覚的なテーブル構造が伝わらないため、Obsidian 同様に `<table>` ウィジェットに置換するアプローチを選択。実装は `Decoration.replace({ block: true, widget })` でテーブルノード全体を置換し、カーソルがテーブル範囲に入ると widget が外れてソース表示に戻る |
| インラインリンク `[text](url)` クリックでノートへ移動（2026-07-13） | `live-preview.ts` の Link ノード処理で `LinkText` 範囲に `data-href` 属性を付与し `mousedown` ハンドラで `openNoteByName` を呼ぶ。外部 URL（http/https）はスキップ。パスにディレクトリが含まれる場合はファイル名のみを抽出してファイル名検索にフォールバックする |
| テーブルセル内のインライン Markdown を HTML としてレンダリング（2026-07-13） | `textContent` では `**太字**` や `[リンク]()` がそのまま表示されていた。`renderInline()` 関数でコードスパン保護 → HTMLエスケープ → 太字/斜体/打消し/リンク変換 → コードスパン復元 の順で処理し `innerHTML` に代入。XSS 対策として生テキストは `escapeHtml()` 済みの上で span/code 要素のみ挿入する |
| 引用ブロックに左バー＋背景＋本文色を追加（2026-07-22） | 「引用の見た目が italic だけで引用っぽくない」との実機フィードバック。`Blockquote` ノードの各行に `Decoration.line({ class: "cm-blockquote" })` を付与し、CSS で `border-left`（`--quote-bar`）・淡い背景（`--quote-bg`）・落ち着いた本文色（`--quote-text`）を当てる。色は nord.css に 3 エイリアスを追加（唯一の色定義元を維持）。ネスト引用は複数ノードが同じ行を跨ぐため行頭位置の Set で重複付与を防ぐ |
| 引用の判定基準を Blockquote → QuoteMark に変更＋`>` マークを隠す（2026-07-24） | フィードバック 2 件への対応。①「`>` の見た目を消したい」→ `QuoteMark`（＋直後の空白）を `touchesSelection`（行単位）で条件付き replace 隠蔽（カーソルのある行だけソース表示）。②「行頭が `>` でない行を引用扱いしたくない」→ 装飾の起点を `Blockquote` ノードの行走査から `QuoteMark` ノードに変更。遅延継続で `>` の無い行が Blockquote に含まれても QuoteMark が無いので装飾されない。line decoration も QuoteMark のある行にのみ付与 |
| 斜体と Enter 継続も QuoteMark 基準へ寄せる（2026-07-26・BUG-011） | 上記変更後、遅延継続行で「斜体だけ残る」「Enter で `> ` が復活」する取りこぼしが判明。斜体は `theme.ts` の `t.quote`（Blockquote ノード基準）から `.cm-blockquote` CSS（QuoteMark 基準）へ移動。Enter は `quoteAwareEnter` を `Prec.highest` で Enter に割り当て、行頭が `>` でない遅延継続行では `insertNewline`（plain）にして lang-markdown の `insertNewlineContinueMarkup`（`Prec.high`）を上書き。行頭 `>` 行・リストは `false` を返し既定に委譲 |
| インラインリンクのテキスト範囲を LinkMark から導出（2026-07-26・BUG-012） | Link 処理が `LinkText` ノードを前提にしていたが `@lezer/markdown` の Link には LinkText が存在せず（子は LinkMark×4 と URL のみ）、`data-href` マークが一度も付かずクリック遷移が無言で失敗していた。テキスト＝最初の `[` と `]` の LinkMark に挟まれた範囲（`marks[0].to`〜`marks[1].from`）として算出し、そこに `cm-md-link`＋`data-href` を付与、`[` と `](URL)` を隠す。太字入りリンクも対象 |
| 箇条書きのインデントを見た目だけで組み直す（2026-08-19） | 「`- ` の列挙のインデントをもっと深く」「0 段目にも行頭の余白を」「折り返しをインデント位置から」「段の範囲がわかる縦ガイド線を」という 4 件の要望。**原文を変えない**方針を採った（`indentUnit` を広げて原文の空白を増やす案は採らない）。0 段目の行頭余白は Markdown の原文では表現できない（4sp 以上はコードブロックになる）ため、どうせ見た目で解くしかない。見た目に寄せれば既存ノートのファイル内容も一切動かない |
| 行頭空白を `Decoration.mark` で「幅だけ」上書きする（2026-08-19） | インデント幅を原文の空白数から切り離すために、行頭空白へ `display:inline-block; width: 段数 × step` を掛けた。`Decoration.replace` にしなかったのは、空白が本物のテキストでなくなるとカーソル移動・Backspace・Shift+Tab が壊れるため。mark なら見かけの幅だけが変わり、編集の挙動は素のまま残る。副作用として、原文の空白の自然幅が箱の幅を超える場合（1 段 4sp 以上で書かれた文書など）は箱からはみ出して少し深くなる — 実害が無いので許容した |
| `ch` で原文の空白幅を打ち消す案を捨てた（2026-08-19） | 当初は `text-indent` に原文の空白文字数ぶんの `ch` を入れて相殺する案を検討したが、`ch` は「0」の字幅であり、プロポーショナルフォントの空白幅はその半分程度。エディタのフォントは設定で変えられる（settings/ui）ため、フォント次第でずれる量が変わる。「幅を固定した箱」なら CSS の長さ値だけで決まり、フォントに依存しない。**ただしこれが成り立つのは、行頭空白と弾丸の**両方**の幅を固定した場合だけ**（下の弾丸の項を参照）。片方でも生テキストのまま残すとフォント依存が戻ってくる |
| 行スタイルを `:has()` から構文木ベースへ移した（2026-08-19） | 旧実装は `.cm-line:has(.cm-list-bullet)` でハンギングインデントを当てていた。カーソルが乗ると弾丸ウィジェットが外れて `:has` が不成立になり、padding ごと消えて行が横に飛ぶ。従来はオフセットが 1.4ch しかなく気付かれなかったが、段ごとに深くすると明確なガタつきになる。段数だけから決まる `Decoration.line` に変えて解消した。**バグ報告があった不具合ではなく、この変更と不可分なので `issues/` には起票していない**（E-21 で検証する） |
| 弾丸の置換範囲を `-` の直後の空白まで広げ、幅を固定した（2026-08-19） | 空白を生テキストのまま残すと、1 行目の本文開始位置が `弾丸 + 空白の実幅` になり、折り返し位置に使っている `--md-list-bullet-width`（1.4ch）と一致するかがフォント任せになる。等幅フォントでは `"• "` が 2ch あり、約 0.6ch ぶん段ごとにずれる。見出し・引用マークと同じく直後の空白ごと置換し、ウィジェットに `display:inline-block; width: var(--md-list-bullet-width)` を与えて定義上一致させた。カーソル判定はマーク 1 文字のまま — 置換範囲の内側にあたる位置はマーク末尾だけで既に含まれており、判定まで広げると Enter 直後（本文先頭）で毎回 `- ` に戻って目障りになる |
| 幅を固定した inline-block に `text-indent: 0` を明示する（2026-08-19・実機フィードバック） | 実機で「`•` の位置が違う」— 段を深くしても弾丸が行頭に貼り付いたまま、本文だけが右へ動く現象。原因は **`text-indent` が継承プロパティであること**。`display:inline-block` はブロックコンテナなので、行に掛けた負の `text-indent`（`-(d*step + bulletWidth)`）を弾丸の span が継承し、**箱の位置は正しいまま中身の「•」だけが左へ** `d*step + bulletWidth` ずれる。結果、弾丸は段によらず同じ x に描かれる。行頭空白の箱も同じ罠を踏むが中身が空白なので見えなかった。両方に `text-indent: 0` を置いて解消。`getBoundingClientRect()` は**箱**を返すため、寸法の実測だけでは検出できない — スクリーンショットを見て初めてわかった |
| 段数は OrderedList も数えるが、装飾は BulletList を祖先に持つ行だけ（2026-08-19） | 番号付きリストの中に `- ` を入れると段が 1 つ潰れて見えるため、深さの計算には両方を数える。一方で番号付きリスト自身の行まで装飾すると要望の範囲を超えるので、祖先に BulletList が無い行は対象外にした |

| 空項目の Enter を `nonTightLists: false` で寄せる（2026-08-19・BUG-025） | 「`- aaaa` → Enter → Enter で項目が消えず、間に空行が残る」との報告。インデント表示の変更が疑われたが、v0.3.0 と同じ `src/` に対する実キー入力テストで**変更前後とも同結果**＝以前からの挙動と確定した。原因は lang-markdown の意図的な分岐で、**タイトな 2 項目リストの 2 番目**でだけ「マークを消す」ではなく「上に空行を挿入して loose 化する」側へ行く。3 項目目以降では消えるので、項目数によって挙動が変わって見えていた。ライブラリが公開している `insertNewlineContinueMarkupCommand({ nonTightLists: false })` で分岐を止められるため、パッチや再実装はしていない。`quoteAwareEnter` と同じ `Prec.highest` のバインドに並べ、引用 3 ケースが 1 バイトも変わらないことを確認して BUG-011 への回帰が無いことを担保した |

## 今後の課題

- 画像レンダリング、コードブロックフェンスの隠蔽（spec.md 未対応ケース参照）
- 番号付きリストのインデント表示は対象外のまま。箇条書きと並べると見た目が揃わない
- 引用の中の箇条書き（`> - x`）もインデント表示の対象外（行頭が QuoteMark のため）
- 0 段目の項目を原文で改行して継続した行（行頭 2sp の継続行）は、折り返し位置が
  空白 2 つぶん右にずれる。幅を固定する箱は原文の自然幅より**狭く**できない（`font-size:0`
  を併用すると `ch` が 0 に潰れて幅指定自体が壊れる）ため。変更前と同じずれ量で、悪化はしていない
- リンクの Ctrl+クリックで外部ブラウザを開く（Tauri の opener プラグインが必要）

## Windows ビルド時の注意（2026-07-17）

devcontainer（Linux）で `npm install` を実行すると `node_modules` に Linux 用バインディングが入る。
Windows 実機でビルドする際は `node_modules` を削除してから `npm install` を再実行すること。
`package-lock.json` 自体は win32 エントリを含むため削除不要。

```powershell
rd /s /q node_modules
npm install
npm run tauri build --no-bundle
```
