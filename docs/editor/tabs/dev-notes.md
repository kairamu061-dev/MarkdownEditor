# editor/tabs 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| 分割しない（タブバー UI とタブの並び・セッション保持を 1 つのサブ項目・1 ファイル `tabs.ts` に置く） | spec 直後の分割検討で、分かれ目の候補は「タブバー（UI）」と「タブの並び（データ）」。ただし並びは永続化もしない UI の内部状態で、バーは並び無しでは何も描けず、並びはバー無しでは操作する手段が無い。片方だけ切り出しても単独で検証できる意味を持たない。コードも約 200 行・1 ファイルで、6 文書を 2 組持つと文書がコードを大きく上回る（agent-rules の code-highlight の反省） |
| 同じノートを複数のタブで開かない（Obsidian からの意図的な差分） | タブごとに独立した `EditorState` を持つため、同じファイルを 2 つのタブで開くと互いの保存で上書きし合う |
| 新しいタブは中クリックと右クリックメニュー。Ctrl+クリックは使わない | ツリーの Ctrl+クリックは multi-select の選択切り替えに使用済み。ユーザ確認のうえ、既存操作を変えない案を採用（2026-11-23） |
| スクラッチ文書はタブにしない（タブ 0 個 = スクラッチ） | `currentPath === null` = スクラッチという既存の意味（自動保存・inline-title・削除）をそのまま使える。ユーザから「実装都合でよい」と回答あり |
| 切り替え・閉じる前の保存に失敗したら操作を止める | `pendingContent` は書き込み先のパスを持たない。止めずに切り替えると、未保存分が失われるか別のノートへ書かれる。リネーム・移動の既存の扱い（「保存できていないため〜できません」）に揃えた |
| 保管庫切り替えの前にも保存を確定する | 従来は確定しておらず、debounce 中の入力は `currentPath` が null になった時点で黙って捨てられていた。タブの全閉じと同じ手順に乗せるついでに塞ぐ |
