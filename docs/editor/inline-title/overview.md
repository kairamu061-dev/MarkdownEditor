# editor/inline-title 概要

## 目的・背景

Obsidian と同様に、編集中のノート名をエディタ画面の最上部に表示し、その場で編集してリネームできるようにする。

現状、開いているノートの名前を確認できるのはサイドバーのツリーの強調表示だけで、サイドバーを閉じている（Ctrl+B）と何を編集しているのか分からない。
またリネームはツリーの右クリックメニューからしか行えず、本文を書きながら名前を直す操作が遠い。

## スコープ

### 作るもの

- エディタ領域の最上部にノート名（`.md` を除いたベース名）を常時表示する行
- タイトル行のクリックで編集モードに入り、Enter / フォーカスアウトで確定してファイルをリネームする
- リネームは既存経路（`renamePath` → `remapAfterRename` → `refreshTree`）を利用し、ツリーの強調・折りたたみ状態も追随させる
- ノートを開いていない状態（スクラッチ文書）では「無題」を編集不可で表示する
- `state.currentPath` の変化（ノート切替・リネーム・移動・保管庫切替）に表示を追随させる

### 作らないもの

- **本文先頭の H1 見出しとの連動**（2026-08-06 ユーザー判断）。タイトル行はファイル名のみを扱い、本文テキストには一切触れない
- タイトル行からの新規ノート作成（スクラッチ文書に名前を付けて保存する動線）
- パンくず表示（親フォルダのパス）・タブ・複数ノートの同時表示
- リネームに伴う被リンク（`[[...]]` / `[](...)`）の自動書き換え

### 対象外の理由

H1 連動は「H1 が無いノート」「H1 が複数あるノート」「手で H1 を消したとき」の挙動をすべて定義する必要があり、仕様が大きくなる。
Obsidian も既定では連動しない（インラインタイトルはファイル名の表示）ため、まずは同じ範囲に揃える。

## 制約

- リネーム前に保留中の自動保存を必ずフラッシュする。自動保存は 700ms の debounce（`SAVE_DEBOUNCE_MS`）のため、本文入力の直後にリネームすると保存が旧パスへ飛ぶ・取りこぼす恐れがある（BUG-017 と同種のリスク）
- フォーカスアウト時の確定・破棄の挙動は既存のツリーリネーム（BUG-016 の対処）と揃える。無条件キャンセルは入力を黙って捨てるため不可
- タイトル入力中のキー操作をエディタのキーバインドに奪われないようにする（既存 `startRename` と同じく `stopPropagation`）
- エディタ（`src/editor/`）は保管庫の知識を持たない方針のため、リネームの実行は file-explorer 側のコールバックに委譲する

## 完了条件

- ノートを開くとエディタ最上部にノート名が表示され、ツリーで別ノートに切り替えると表示も切り替わる
- タイトルを編集して Enter で確定するとファイルがリネームされ、ツリーの表示と強調が追随する
- フォーカスアウトでも、妥当かつ変更ありなら確定される（入力が黙って消えない）
- 同名衝突・空文字・パス区切り文字の入力でファイルが壊れず、ステータス表示で伝わる
- 本文入力の直後にリネームしても、直前の入力が失われない
- スクラッチ文書では「無題」が表示され、編集モードに入らない

## 画面イメージ

```
+-----------+-----------------------------+
| ☰  MarkdownEditor          ─   ▢   ✕   |  ← 既存のタイトルバー
+-----------+-----------------------------+
| ツリー    | 買い物リスト                |  ← 追加するタイトル行
|           +-----------------------------+
|           | # 買い物リスト              |
|           | - 牛乳                      |  ← 既存のエディタ
|           | - パン                      |
+-----------+-----------------------------+

クリックすると入力欄になる:
           | [買い物リスト____________]  |  ← Enter / フォーカスアウトで確定
```
