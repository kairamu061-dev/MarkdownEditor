# editor/inline-title テストケース

## E2Eテスト

| ID | テスト名 | 前提条件 | 手順 | 期待結果 | ステータス |
|----|---------|---------|------|---------|-----------|
| E-01 | ノート名の表示 | 保管庫を開いている | ツリーでノートをクリックする | エディタ最上部にノート名（`.md` なし）が表示される | [ ] |
| E-02 | ノート切替への追随 | 複数ノートがある | ツリーで別のノートに切り替える | タイトル行の表示が新しいノート名に変わる | [ ] |
| E-03 | サイドバーを閉じても残る | ノートを開いている | Ctrl+B でサイドバーを閉じる | タイトル行は表示されたまま。何を編集中か分かる | [ ] |
| E-04 | Enter でリネーム | ノートを開いている | タイトルをクリック → 名前を変更 → Enter | ファイルがリネームされ、ツリーの表示と強調も追随する | [ ] |
| E-05 | フォーカスアウトで確定 | 同上 | タイトルをクリック → 名前を変更 → 本文をクリック | リネームされる（入力が黙って破棄されない・BUG-016 と同方針） | [ ] |
| E-06 | Escape で破棄 | 同上 | タイトルをクリック → 名前を変更 → Escape | リネームされず、元の名前の表示に戻る | [ ] |
| E-07 | **本文入力直後のリネーム** | ノートを開いている | 本文に 1 文字入力し、**700ms 以内に**タイトルを変更して Enter | リネーム後のノートを開き直すと、直前に入力した 1 文字が残っている（flushSave が先行する） | [ ] |
| E-08 | 同名衝突 | 同じフォルダに `A.md` と `B.md` | `B` を開いてタイトルを `A` に変更 → Enter | `同名の項目があります` が表示され、入力欄は残る。ファイルは変わらない | [ ] |
| E-09 | 空文字 | ノートを開いている | タイトルを空にして Enter | 確定されず編集状態のまま。ファイルは変わらない | [ ] |
| E-10 | パス区切り文字 | ノートを開いている | タイトルを `sub/名前` にして Enter | 確定されず編集状態のまま（フォルダ移動は D&D の役割） | [ ] |
| E-11 | スクラッチ文書 | 起動直後（ノート未オープン） | タイトル行を見る / クリックする | `無題` が淡色で表示され、クリックしても編集状態にならない | [ ] |
| E-12 | 保管庫切替で戻る | ノートを開いている | フッタのスイッチャで別の保管庫へ切り替える | タイトル行が `無題` に戻る | [ ] |
| E-13 | ツリーのリネームに追随 | ノートを開いている | ツリーの右クリック → リネームで名前を変更 | タイトル行の表示も新しい名前になる | [ ] |
| E-14 | D&D 移動に追随 | サブフォルダがある | 開いているノートを別フォルダへドラッグ移動する | タイトル行の表示（ベース名）は変わらず、リネームも壊れない | [ ] |
| E-15 | キー入力がエディタに漏れない | ノートを開いている | タイトル編集中に Ctrl+B などを押す | サイドバーが開閉しない（`stopPropagation`） | [ ] |
| E-16 | blur 失敗時にフォーカスが固定されない | 同名衝突を起こせる状態 | タイトルを既存名に変更 → 本文をクリック（blur で確定失敗） | エラー表示後、本文をクリックし直せる。フォーカスがタイトルに奪われ続けない | [ ] |
| E-17 | **ツリーのリネームでも取りこぼさない** | ノートを開いている | 本文に 1 文字入力し、700ms 以内にツリー右クリック → リネームで確定 | リネーム後のノートに直前の 1 文字が残っている（T-8 で追加した flush） | [ ] |

## 補足

- 本フィーチャーには純粋なロジック関数がほとんど無く（表示名の算出と入力検証のみ）、
  価値の大半は DOM 操作と既存フローとの結合にあるため、ユニット／インテグレーション層は設けず E2E に寄せている。
- E-07・E-17 が本フィーチャー特有の最重要ケース。debounce（700ms）とリネームの順序に関する取りこぼしで、
  BUG-017 と同種のデータ消失につながる。
- E-16 は実装中に気づいた注意点。blur 起因の確定失敗でフォーカスを奪い返すと、
  外側をクリックするたびに blur → 失敗 → 再フォーカスが繰り返されて抜け出せなくなる。
- 開発環境（Linux devcontainer）では `vite build` が動かない（共有ツリーの `node_modules` が
  Windows 用のため。BUG-023 参照）。型チェック（`tsc --noEmit`）は通過済みで、
  上記の実行確認は Windows 実機で行う。

## ステータス凡例

- `[ ]` 未実施
- `[~]` 実施中
- `[x]` 合格
- `[!]` 不合格
