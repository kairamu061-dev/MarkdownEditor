# editor/inline-title 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| サブ項目に分割しない（2026-08-06 評価） | UI 面が 1 つ・配線が 1 経路で、分割しても片方だけでは検証不能。統合の例外条件を満たす |
| CodeMirror の拡張ではなく兄弟要素にした | 本文の一部にすると文書テキストに影響しうる。H1 連動をしない方針とも整合し、エディタの状態管理から完全に切り離せる |
| `state.currentPath` への代入を `setCurrentPathInternal` に集約した | 代入箇所が 4 つ（`setCurrentPath` / `openNote` / `remapPrefix` / `applyVault`）に散っており、各所から個別に通知を足すと必ず漏れる。唯一の代入経路にしてそこで通知する |
| `onCurrentNoteChanged` は登録時に 1 回即座に呼ぶ | 購読側が初期表示のために別途 getter を呼ぶ必要をなくす。`main.ts` の配線が 1 行で済む |
| リネームの実処理は file-explorer 側（`renameCurrentNote`）に置いた | `src/editor/` は保管庫の知識を持たない方針（wikilink / live-preview と同じ）。inline-title は表示と入力 UI だけを持ち、確定はコールバックに委譲する |
| 確定順序を「flushSave → 検証 → rename」に固定した | 自動保存は 700ms の debounce。順序が逆だと保留中の本文が旧パスへ書き戻され、リネーム後のノートから消える（BUG-017 と同種のデータ消失） |
| `flushSave` 後に `pendingContent` が残っていたらリネームを中止する | 保存自体が失敗している状態でリネームすると、未保存の内容が旧パスに取り残されて到達不能になる。`保存できていないため名前を変更できません` を表示して中止する |

## 発生した問題と対処

| 問題 | 対処 |
|------|------|
| blur 起因の確定が失敗（同名衝突など）したあとに `input.focus()` で戻すと、外側をクリックするたびに blur → 失敗 → 再フォーカスが繰り返され、Escape 以外で抜けられなくなる | まだ入力欄にフォーカスがある（＝ Enter 経由の失敗）ときだけ `select()` する形に変更。blur 経由の失敗では入力欄を残すだけにして、既存のツリーリネームと同じ挙動に揃えた。test-cases の E-16 として記録 |
| リネーム成功時、`remapAfterRename` の通知が `await` の最中に届くため、購読側の `setPath` が編集中の入力欄を消してしまう懸念があった | `setPath` は編集中（`editing === true`）なら再描画せず値だけ更新する。確定処理の側で `await` 完了後に `render()` を呼ぶため、新しい名前で正しく描画される |
| 開発環境（Linux devcontainer）で `vite build` が実行できない | 共有ツリーの `node_modules` が Windows 用（BUG-023）。vite を別 prefix に入れても rollup をプロジェクト側から解決してしまい回避不可。プロジェクトの `node_modules` は Windows のビルド環境を壊さないため触らない方針とし、型チェック（`tsc --noEmit`、`node node_modules/typescript/bin/tsc` で実行可）までを開発環境で確認し、実行確認は Windows 実機に委ねた |

## 設計からの変更点

| 変更内容 | 理由 |
|----------|------|
| `renameCurrentNote` に「保存失敗時は中止する」分岐を追加（design.md には未記載だった） | `flushSave` は失敗しても例外を投げず `pendingContent` を保持して戻る実装（BUG-014 の対処）。設計時に見落としていたが、この状態でリネームすると未保存内容が失われるため実装時に追加した |

## 今後の課題

- リネームしても被リンク（`[[旧名]]` / `[](旧名.md)`）は旧名のまま残る。Obsidian は追従するが、
  保管庫全体の走査と書き換えが必要なため今回は対象外（spec の未対応ケース参照）
- スクラッチ文書は「無題」の固定表示で、タイトルから新規ノートを作る動線は無い
- 長いノート名は CSS の `text-overflow: ellipsis` で省略表示される。全体を見るにはタイトル属性
  （ホバー時のツールチップ、相対パスを表示）に頼る形
